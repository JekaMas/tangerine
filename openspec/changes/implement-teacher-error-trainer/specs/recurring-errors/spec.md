## ADDED Requirements

### Requirement: FOS-01 Explicit per-speaker recurring settings
The application SHALL offer an optional recurring pattern and configurable70–95%
target per speaker, default85%, optional rule guidance, retained role choices and
advanced overrides. Explain per-opportunity frequency, practice-setting origin,
pattern counting and explicit-zero behavior without changing legacy defaults.

#### Scenario: FOS-01 Independent profiles and retained inputs
- **GIVEN** two active roles and optional recurring profiles
- **WHEN** their settings or the active count change
- **THEN** only active enabled roles are submitted and hidden choices are retained
- **AND** Automatic/absent profiles preserve the original behavior
- **AND** zero errors disables recurrence and contradictory exact counts are explained

### Requirement: FOS-02 One admitted opportunity ledger
The generation pipeline SHALL create a correct canonical script and a specific
same-speaker recurring rule with complete canonical/surface opportunities, exact
rounded mutation quota and preserved correct exceptions. Admit new output once;
freeze the accepted ledger and never infer errors from accent alone.

#### Scenario: FOS-02 Quota and counterexamples
- **GIVEN** a selected speaker and a specific rule with eligible contexts
- **WHEN** mutations are admitted
- **THEN** the saved changed subset equals the documented rounded quota
- **AND** wrong-speaker, duplicate, mislocated, unkeyed or changed-correct contexts fail
- **AND** actual finite-sample percentage is distinguishable from the requested target

### Requirement: FOS-03 Persistent group and accurate scoring
The candidate, manifest, rendered key and post-submission result SHALL retain the
recurring rule and all occurrences as one scoring unit. A correct common finding
can identify it once; unrelated events and correct exceptions remain distinct.
Preserve all existing formulas, optional explanation judgments and saved attempts.

#### Scenario: FOS-03 Shared rule through the real owners
- **GIVEN** an admitted recurring group and a listener's common-rule answer
- **WHEN** it is stored, rendered and evaluated
- **THEN** the native score counts one pattern and results show actual opportunity counts
- **AND** an assertion about a correct exception or another speaker gains no false credit
- **AND** optional reasons cannot erase supported primary credit

### Requirement: FOS-04 Actual UI, speech and LLM evidence
Development SHALL verify real controls and an actual admitted included/local
generation-to-result flow, retain native/Lab context and independent expectations,
and exercise repeated acoustic scopes without losing their individual scoped mutations.

#### Scenario: FOS-04 Repeated pronunciation and actual use
- **GIVEN** installed local speech and existing included-only text access
- **WHEN** recurring examples and the ordinary UI flow execute
- **THEN** real saved outputs, contexts, counts and results remain inspectable
- **AND** repeated scopes cannot overwrite each other or alter a correct exception
- **AND** no paid fallback, human-review requirement or universal empirical claim is added
