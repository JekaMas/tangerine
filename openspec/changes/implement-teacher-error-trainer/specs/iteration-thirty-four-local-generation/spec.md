## ADDED Requirements

### Requirement: I34 Installed-local generation repair
Selected local generation SHALL run through the existing frozen preparation, provider, mutation admission and persistence owners, as QUAL-05 specifies. The current user authorizes a bounded comparison of repair alternatives on fixed functional cases with installed models. It SHALL NOT add a model sweep, installation, purchased usage, hidden hosted fallback, repeated saved-data admission or an ordinary-use qualification gate.
Mechanical new-output projection SHALL follow specification/v2/docs/generation-contract-details.md. When a repair changes only native projection and leaves model-visible inputs unchanged, retained actual replies MAY be reused through explicitly labelled native projection/persistence tests. Such replay SHALL NOT be represented as fresh inference, new provider usage or new generation latency.

#### Scenario: I34 Local clean and mutation persistence
- **WHEN** the selected installed-local profile prepares the fixed positive and zero-error requests
- **THEN** actual clean text, replies, normalized candidate, replayable manifest and frozen settings are retained, the selected positive errors and valid corrections satisfy independent expectations, and the zero-error control does not invent mistakes

#### Scenario: I34 Honest failed generation and recovery
- **WHEN** a local runner fails, the deadline expires or the reply violates the mutation contract
- **THEN** the existing owner preserves saved clean text and failed receipts, creates no fabricated key, permits explicit recovery, and never changes frozen profiles or silently dispatches to a hosted service

#### Scenario: I34 Bounded comparable repair alternatives
- **WHEN** plain and schema-guided decoding are compared on the declared common functional requests
- **THEN** the report separates admission from linguistic correctness, records TP/FP/FN/TN and independently valid corrections, defines precision/recall/accuracy denominators and unavailable values, preserves failures, and reports actual latency/tokens/resource observations and zero local API charge without claiming population benchmarks

#### Scenario: I34 Actual native and Lab evidence
- **WHEN** iteration34 is accepted
- **THEN** every owned inference is joined to its actual serialized dispatch, frozen model/context and retained reply/receipt, local Lab export and readback preserve the selected experiment, and directly affected positive/negative tests pass on committed-clean source with unchanged product/source scopes
