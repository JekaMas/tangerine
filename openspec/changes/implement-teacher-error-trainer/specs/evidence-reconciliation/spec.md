## ADDED Requirements

### Requirement: TRACE31 Historical literal evidence reconciliation
The development evidence graph SHALL reconcile every one of the 1,909 historical
planned or blocked case identities at revision
ab91a998903f537c6c57e6875a85e5943d54a3b9 with its original input, independent
expectations, inspected successor assertions and actual observations. Exact
component reuse SHALL retain its original scope and receipt. A passing sibling,
matching category, report label or aggregate count SHALL NOT promote an
unobserved assertion. Literal tests SHALL use existing production owners;
genuine missing behavior, data, qualification and observations SHALL remain
explicitly open. This reconciliation SHALL add no product validation gate,
provider call, installation, benchmark campaign or learner prerequisite.

#### Scenario: TRACE31 Original population and independent expectations
- **GIVEN** the frozen original graph, fixture collection and all 1,909 identities
- **WHEN** reconciliation is registered in the canonical graph and ledger
- **THEN** every original identity, scenario, polarity and independent expectation is preserved
- **AND** omissions, duplicates, easier substitute fixtures and unrelated test identities are rejected by the development check

#### Scenario: TRACE31 Typed observations and literal execution
- **GIVEN** newly executable original arithmetic, population, span and edit fixtures
- **WHEN** their real owners run or exact unchanged component observations are reused
- **THEN** retained native output identifies every claimed physical test and its actual outcome
- **AND** a skipped, failed, missing or unrelated observation cannot satisfy the literal, even with a successful summary

#### Scenario: TRACE31 Exact partial reuse without promotion
- **GIVEN** retained category context and recipe assertions with unchanged source and actual native receipts
- **WHEN** only some steps of an original complete scenario match
- **THEN** those exact components retain their actual proof and unmet assertions remain open
- **AND** constructed arithmetic or an intended recipe cannot become an observed semantic, acoustic or empirical result

#### Scenario: TRACE31 Unchanged product and accepted history
- **GIVEN** accepted physical test registrations and the original runtime/data definitions
- **WHEN** stale specification-only blocker descriptions are corrected
- **THEN** existing accepted cases, runtime behavior, all 122 categories, 42 formulas and eleven source scopes remain unchanged
- **AND** inaccessible releases, finite provider observations, incomplete browser verification and a contradictory historical fixture are not relabelled complete

#### Scenario: TRACE31 Static validation is not execution
- **GIVEN** an original scope fixture with 400 static checks and zero actual behavior runs
- **WHEN** the existing evidence runner reads a successful summary without matching typed case observations
- **THEN** no executed behavior is reported
- **AND** a forged pass without the required observation identity remains missing or stale
