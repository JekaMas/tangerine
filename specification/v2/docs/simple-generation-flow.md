# Main flow: generate, mutate, synthesize, listen and check

This is the ordinary product flow requested by the user. It supersedes any earlier interpretation that a complete empirical mistake corpus, native audio examples, phonetic calibration collection, benchmark or separate case-review action is needed before generating and using an exercise. The five user-visible steps are: user request -> LLM clean text -> LLM mutations -> generated/stored audio -> listener answer and LLM checking/comments/scoring. Every new exercise is generated on demand. No pregenerated exercise corpus, seed bank or batch generation is required at setup or before use. Saving an exercise after generation enables replay; it does not turn a prebuilt bank into the primary flow. All corpus/import/benchmark features and all 122 categories and 42 metrics remain available as optional resources.

## User input and defaults

The main form asks for topic, number of speakers and approximate text length in words. English level and broad mistake categories are optional. contracts/exercise-request.schema.json owns these fields; blueprint-write accepts the simple exercise_request and the server expands it to the existing full blueprint. Advanced blueprint fields remain supported. The UI handles internal operations without asking the user to configure an API, identities, schemas or review stages.

topic is the exact user topic; speaker_count is a positive integer; text_length_words is a positive approximate word target. One speaker selects monologue; more than one selects dialogue. Assign stable speaker IDs s1..sN and a configured voice per speaker. Speaker count means distinct dialogue roles, not necessarily distinct voice models; shared voices remain explicit. Generate speech for each assigned turn in order. english_level may be A1–C2 or null. Null means no CEFR constraint, not a hidden B1 requirement or an observed proficiency rating. Every requested speaker participates.

category_families uses grammar, lexis, pronunciation.segmental, pronunciation.suprasegmental, fluency, discourse and pragmatics_register. pronunciation is also a broad selection expanding to both pronunciation domains. Empty/omitted means automatic selection. The mutator chooses concrete leaves; the user need not specify 122 IDs. The eight acceptable-variant leaves remain available as optional controls. mutation_count is optional: null means the mutator chooses a suitable number; an explicit 0 permits the existing control-only exercise. Existing advanced exact leaf/count constraints remain available and override automatic selection, without erasing an explicit broad family request.

With automatic selection, choose mutations renderable by the selected audio backend. An explicitly requested family remains requested; explain an unavailable realization and offer another configured backend or another request rather than silently remove it. This is an action failure, not an extra provider-certification process. Workspace configuration.speech_profile owns the default synthesis profile and case_review_enabled defaults false. Voices/register/locale/task-component defaults come from the explicit preparation_defaults/configuration-registry settings and are saved visibly with the resulting blueprint. Duration_ms_min/max can be null for word-length requests; actual duration is measured after synthesis. Existing explicit duration bounds remain supported. Do not convert a word target into an invented measured duration.

Text word count is the number of nonempty whitespace-separated tokens in utterance text, excluding speaker labels. Contractions/hyphenated words without whitespace count once. Store actual canonical and mutated word counts in generation provenance. Length is approximate by default: show actual length, preserve the requested target and offer regenerate/edit when desired; do not add a hidden exact-length rejection or repair loop.

## 1. LLM creates the clean text

Use the configured case_generation role with phase=canonical_text and prompts/canonical-v1.txt. Input is the topic, speaker/length/optional-level settings and public task context. No corpus record is required. source_record_ids/source_excerpts may both be empty. Optional acquired references can enrich a request when selected under their source terms.

The output uses the existing case-candidate shape: coherent ordered utterances with stable speaker IDs, canonical_text equal to surface_text, planned_units=[] and candidate status. The first phase deliberately has no injected mistakes. Its target-count constraints are not mutation-completion assertions. Save the exact canonical record and hash before the mutation phase. Accidental baseline defects can be corrected within normal output repair; no separate reviewer or empirical example is required.

## 2. Apply novel mistake mutations and save their list

Use case_generation phase=mutation with the saved canonical_script and canonical_script_sha256. The selected mutation recipes and broad/exact category choices guide an independent transformation of that fixed text. The configurable LLM generates the mutations for this user request: it chooses the contextual opportunities, changed wording or acoustic intents and complete repairs/rationales. Local code validates, materializes and replays that returned edit list; it does not supply an alternative recipe-only mutation generator or fall back to a pregenerated error bank. The mutation output preserves the canonical text exactly, carries surface_text and emits planned_units as the complete mutation list/key. Actual source references are optional; ordinary generated data have authored/LLM origin.

“Out of distribution” here means novel instances, contexts and combinations relative to the selected recipe illustrations, optional reference examples and prior exercise instances. Do not repeatedly copy a catalogue example such as She work here. Vary lexical material, turn roles, topic and mutation placements while preserving the chosen error definition. Keep a reproducible seed and method version with the exact edits. Exact duplicate examples can be compared after NFC/casefold/whitespace folding for novelty selection; this comparison does not alter canonical text, answer offsets or grades. Report novelty basis and any duplicate finding. It is not proof that text is absent from a proprietary LLM's training distribution. No corpus-wide OOD score or held-out dataset is required for ordinary use. A separately requested empirical held-out evaluation uses its actual frozen population.

Each mutation uses a stable unit ID, affected utterances/spans, original and changed text or acoustic intent, exact/accepted/secondary categories, judgment, severity/weight, valid repairs and required/forbidden explanation propositions. The existing type=mutation provenance asset retains the canonical/surface hashes, recipe/version/seed, request settings, actual word counts and edit list. New lexical/contextual instantiations remain within the original taxonomy. Unknown source phenomena remain retained raw data rather than invented new IDs.

The actual generated content uses the builtin GENERATED-EXERCISE provenance source, separate from all eleven original full-release sources. It is not an acquired TET-GOLD-1 benchmark or an external corpus quotation. After real rendering, project shared planned_units fields into ground-truth.units; assign actual case/audio identities, turn intervals from final assembly, mutation evidence IDs, source provenance, verification=candidate and difficulty_evidence_ref=null. Empty optional review_decisions is valid. Use the real containing-turn interval when word timing is unavailable; never fabricate phone or word boundaries. The ordinary key can be used with candidate acoustic-confirmation status and visible warnings. Optional diagnostics can append supported evidence/key revisions without rewriting the original list.

For textual categories, the changed text is what is spoken. For pronunciation/prosody/pauses, retain the intended words and add the existing phoneme/prosody/pause render operations at the mutation location. Spelling an error is not automatically a pronunciation mutation. These special operations remain available; ordinary grammar/lexis text generation does not depend on acoustic example corpora. Controls carry expected_judgment=acceptable and do not become mistakes.

## 3. Generate and store the audio

The app renders the mutated script using either the configured local TTS backend or an external generative speech service. It does not play corpus recordings as a prerequisite. Speech profiles are interchangeable through the existing render-plan/speech-render-request/result contract; profiles explicitly state their actual supported operators and voices. No arbitrary uploaded XML or new public API is needed.

The concrete local baseline is Kokoro-82M through the existing Python speech worker, with KPipeline lang_code=a for en-US or b for en-GB, configured voice and speed. Basic local support is literal text, ordered speaker turns and explicit silence assembly; fine IPA/prosody operators require a documented implementation in that adapter and are not promised from plain text alone. Baseline voices are af_heart/am_adam and bf_emma/bm_george. Default device is CPU; GPU is optional. The future release includes the inference dependency in the speech build, records the actual locked dependency/model/voice digests, and stores downloaded model assets in a persistent local cache. Local setup provides the visible `sh scripts/tangerine model-setup` action described in docs/local-delivery.md; selecting it does not ask for a speech API key. This specification increment installs/downloads nothing and does not claim a measured platform/performance result.

The existing Azure profile and all four default voices remain the external service baseline. Other installed/configured speech adapters can be selected. LLM and speech configuration remain separate. Local TTS needs local model files; an external service needs its own credentials. The existing DeepSeek fast profile can generate text/mutations and check text answers with either speech backend.

Render exact surface wording, retain speaker/turn order and intended errors, assemble a 24 kHz mono PCM16 WAV, measure actual duration and save final audio bytes with the mutation list/canonical/mutated script and actual provider/model/profile provenance. Reopening/replaying uses stored audio, not new synthesis. Synthesis failure leaves the saved text/list and offers retry; it creates no playable placeholder. Reference audio, ASR, forced alignment, pronunciation assessment and an extra LLM case review are optional enrichment/diagnostics. They do not precede ordinary use. Known audio deviations can be handled by the existing key-revision flow; requested IPA/prosody never becomes invented observed sound.

Each existing foreground generate/render operation retains its 270-second deadline. Canonical generation has a 90-second cap and mutation a 150-second cap within the generate operation, each limited by remaining time and the existing persistence reserve. Retries reuse a completed matching canonical stage rather than rewrite its text; an explicit new-text request starts a new canonical version. Rendering follows as the existing foreground operation. The UI can orchestrate these calls under one Generate exercise action without a background queue or hidden recurring loop.

## 4. Listen and submit a text answer

Open the stored exercise, show its public topic/task context and audio player, and let the listener describe heard mistakes in free text. Transcript, specific mutations, target count and answer key stay hidden until submission. Preparation and listening are separate views even in the same local workspace. Save the exact answer before any evaluation call. No account or human peer review is needed.

## 5. LLM compares the answer with the mutation list

The saved mutation list is the answer key for the ordinary authored exercise. Bind it to the exact canonical/mutated/audio version. Existing extraction/mapping stages interpret each original answer assertion and compare its location, stance, category, repair and explanation with the original clean text, actual mutated text, mutation list and context for the same saved exercise. The existing evaluation-key.utterances supplies both canonical_text and surface_text, and evaluation-key.units supplies the mutation obligations/corrections; no separate corpus retrieval is needed. The checking model need not hear the audio again to perform this comparison. Matching accepts descriptions, category synonyms and valid alternative corrections; it does not require literal wording from the list.

One detected mutation counts once. Duplicate fragments do not multiply credit. A wrong category does not erase a correctly localized detection. Missed mutations, supported false assertions, acceptable controls, valid repairs and explanations use the unchanged scoring rules. A plausible additional actual defect can trigger LLM key reconsideration, preserving the old version; it is not automatically a false positive merely because generation omitted it. If an acoustic fact is genuinely disputed, available measurements or an audio-capable adapter can help; text-only DeepSeek is not labelled as listening to audio. There is no mandatory separate acoustic-review pass before this answer comparison.

## 6. Score and recommend practice

The LLM supplies semantic decisions; native code retains all 42 unchanged metric formulas and calculates the applicable exercise metrics and existing composite. Corpus, multi-rater or teacher-population metrics use only their actual required populations; unavailable inputs remain N/A with a reason, not an invented per-answer statistic. Show the score, found/missed mutations, unnecessary corrections, explanations and permitted repairs. The configurable feedback LLM supplies actionable practice recommendations tied to those findings: what to listen for, which rule/contrast to practise, and a new illustrative practice example. Such examples are labelled newly generated practice, not unheard defects in the recording or corpus quotations. Fluent paraphrases do not require a human signature. Feedback failure preserves the score and saved answer; retrying recommendations does not regrade.

## Data role and limits

Required per exercise: the user's settings, generated canonical text, actual mutation list/repairs, mutated render input, actual stored audio, saved answer and actual LLM decisions/score/recommendations. These are created during use. A complete native mistake corpus, observed global category frequencies, native sample audio and the 732-stimulus benchmark are not dependencies of this flow.

All original full corpus scopes remain in the project for optional pattern enrichment, authentic examples, empirical frequencies, imports, accent/reference comparisons and evaluation. Corpus completeness reports remain honest but do not describe missing source data as a blocker for this independent authored flow. Reference recordings are useful for testing subtle speech behavior, not required training inputs for each new text mutation. Special acoustic targets still need a renderer that can request them; lack of a native corpus does not remove the target feature.

Primary local-TTS references: [Kokoro inference owner](https://github.com/hexgrad/kokoro) documents KPipeline, language selection and 24 kHz audio; [Kokoro model/voices](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md) supplies the English voice inventory. These references support a specified future adapter, not an executed inference or installed model.

Prompt/context versions, actual inputs/outputs, diagnostic quality comparisons and local traces can be managed through the optional LLM Lab in llm-lab.md. The main flow needs no Lab, prompt approval, benchmark threshold or human review; saved local bundles own normal execution.

Exact expansion, replayable edits and candidate-to-key projection are defined in generation-contract-details.md.

Data dependency scope is specified in product-data-relevance.md: the generated key/actual answer supports scoring and targeted recommendations without source frequency, real participant cohorts or benchmark completion. Missing optional source contexts affect only their explicitly selected actions.

Answer checking follows answer-components-v2 in answer-component-scoring.md: independent correction correctness plus an optional explanation assessment whenever supplied, without omission penalty or rationale-to-correction cancellation. Native code supplies the main score and separate applicable explanation score; feedback discusses both.

Current preparation persistence/resume is defined by preparation-persistence.md and preparation-state/preparation-settings schemas. Generation must be self-contained under self-contained-generation.md; no private contextual fact determines a scored mistake. Key repair uses key-repair-projection.md and the existing LLM operation. These are written contracts, not implemented behavior.
