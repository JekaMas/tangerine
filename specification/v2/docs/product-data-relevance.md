# Product use of data and evidence dependencies

This document and domain/product-data-relevance.v1.json own the current mapping of remaining inputs to product uses. They supersede broad completion requests in earlier remaining-input audits without rewriting historical receipts. The user authorizes removing unneeded requirements; all122categories/recipes,42grade formulas,11original full-source scopes, existing source fields and optional features remain. This adds no runtime configuration registry or new service.

## Ordinary generated exercise

Topic/speaker count/length → configurable LLM clean text →122recipe-guided novel mutations and saved key → selected local/service audio → stored playback → free-text answer → LLM key comparison → native42formula scores and recommendations. These steps need the configured resources and their own saved artifacts. They need zero external corpus records, reference recordings, native instruments, empirical frequency tables or human participant collection. The generated mutation list supplies the expected errors and contextual corrections. Ordinary recommendations use observed misses/overcorrections/categories from that answer, without empirical prevalence or rated difficulty. Corpora can supply selected contextual examples; they never replace the authored key.

Source archive support is still full-source support. External acquisition is an optional operator action with its own status, not unfinished product-definition work. A configured unavailable source is visible in source status but does not block generation, mutation, answer checking, unrelated import, startup or selected AI development. If a user selects an unavailable source context, report that source unavailable and offer an explicit independent-generation or available-source choice; do not silently substitute data or another source. Existing source controls/status/operations suffice.

## Scope of failures and completeness

An archive may complete raw intake while some fields remain raw_only. Its normalized-complete report needs only actual bindings for the documented meanings it claims; source dictionaries and original-use terms remain required for that selected semantic/reuse action. Never discard native members or invent missing terms to call a full source complete. Corpus source full scopes are unchanged. Questionnaire/interview/pedagogy scales may remain original archived data; they do not need an application scoring implementation and are never converted into Tangerine42formula grades.

The pinned L2 mirror can support native parsing, reference examples and measurements with its exact origin/counts. Unknown official equivalence or an unexplained aggregate-count discrepancy affects those specific equivalence/reconciliation claims. It does not turn structurally valid records into errors or require a maintainer response before use. Normal file/clock/label correctness and actual source terms still apply.

Duplication is not new empirical coverage. A48kHzrepresentation, an earlier release or a final publication-format document remains separately named/preserved if available or selected, without becoming a prerequisite for using a complete acquired16kHzrepresentation or the current pinned version. The original11full-source identities and declared supplemental full scopes are not shortened to make acquisition claims pass.

A full122leaf/732stimulus benchmark still means that exact complete population. A selected developer experiment needs meaningful positive/negative cases for the changed property and its affected pipeline, using labelled constructed or permitted imported references. It does not need all leaves, all sources or732stimuli. Partial experiments report selected population, unknown/untested categories, label origin and circular-reference limits. Genuine participant collection only supports a separately claimed empirical participant/difficulty result. New units remain unrated; that does not prevent scoring or recommendations.

Actual main-flow builds, provider/local speech, audible mutation realization, stored playback and semantic answer-checking acceptance remain necessary future engineering evidence. Do not remove them as research overhead. Verify the concrete configured backend/voice/platform being offered; every possible future vendor/voice/platform is not required first. Optional ASR/assessment/reference import requires actual corresponding evidence when selected, without inventing acoustically confirmed results from text. The latest mandatory MLflow development route and controlled prompt/context/call evidence remain intact; no Lab is required for ordinary downloaded use.

## Removed from the product completion checklist

Academic identity provisioning; vendor account/simulator subscriptions and mandatory private API access; adopting or reconstructing source questionnaire/interview/pedagogy scales; institutional study/participant recruitment; certifying a mirror against unavailable official bytes or awaiting an aggregate-count explanation; obtaining every duplicate high-resolution/third-party representation; final publisher-file retrieval/paper reproduction/earlier-release acquisition; all-leaf empirical frequencies/mappings or732stimuli before ordinary use/selected development; universal provider/accent/platform qualification. These can remain source history, explicitly selected optional data/analysis, or specific claims. They are not launch/setup dependencies or unresolved product decisions.
