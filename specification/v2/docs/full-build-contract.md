## Acoustic production and mutation ownership

For a new mutation result, every acoustic/temporal planned unit has its matching edit(s); textual/control units need none. Stable unit/utterance IDs and half-open surface codepoint scope agree with existing planned units. Canonical phase returns [] and never mutates audio. Historic absent fields mean empty/null; new acoustically targeted preparations cannot use that historic default to omit requested targets.

Native compilation produces acoustic-production-plan after a generated source piece exists. It resolves target scope to actual source-piece sample intervals from returned timing/alignment, or the whole explicitly rendered target-word/phrase piece. It never estimates phoneme position from character proportions. For the local controlled route use the actual decoder-duration alignment defined below; selected provider timing must identify an actual source clip and its clock. Unavailable finer boundaries produce a named incomplete operation retaining the key/clean text. The production plan is an immutable child of render-plan: its render_plan_sha256 identifies the core render plan before adding production_plan_asset_id; the core digest excludes this optional child reference and plan_sha256. JCS hashes freeze all other core fields. This avoids circular hashes. Final private provenance records both IDs/hashes. LLM controls are requests; actual final audio remains the stimulus.

All122 rows in domain/acoustic-production.v1.json are the finite production route table. Existing text/context/control recipes preserve their full procedures. Phoneme recipes use the already specified scoped Kokoro phoneme adapter or an explicitly selected compatible provider. The five recorded_contrast rows now create a paired clean/altered recording during the audio phase rather than require a downloaded recording. Existing authentic recordings remain optional import/reference inputs. No extra prompt call or reviewer is required to compile native transforms.

The native controller contract uses the same services/speech process and private assets, not a new service/API:

- phone_pair: render the reference and changed full target-word/phrase phone strings with the same frozen voice/model/settings using kokoro-phonemes-v1, or a chosen provider's supported target-local pronunciation operation. Preserve each actual clip/receipt. Context before/after is rendered separately only at existing phrase boundaries. Full phrase sequences are required for linking/assimilation so word fragments do not silently replace connected speech. The mutated clip alone enters the stimulus; the paired clip is private until feedback or diagnostics.
- vowel_duration: manipulate only the identified vowel interval with Praat DurationTier via overlap-add; duration_ratio is target_duration/source_duration, positive. Defaults specify0.45 for the original controlled short-vowel demonstration; this is a deliberate per-item contrast, not a universal phonetic cutoff. Copy all other source samples unchanged except the explicit boundary splice. Retain pitch/formant measurements and the reference clip when reporting actual quality preservation.
- pitch_duration: create Praat Manipulation with step0.01s, floor60Hz, ceiling500Hz, replace PitchTier and/or DurationTier and obtain overlap-add resynthesis. Pitch point fractions are increasing in[0,1]; semitones are target offsets relative to100Hz, converted by100*2^(s/12). Null/empty pitch keeps the original tier. Positive duration_ratio sets a constant DurationTier factor inside the scope. For pitch_range, measure reference voiced semitones, freeze median m, and replace each voiced point s with m+2*(s-m). Explicit gain multiplies by10^(gain_db/20) on that interval; no secret normalization of a target. Do not invent F0 for unvoiced intervals; an insufficient voiced interval is not_measurable with reason. Stress parameters are production cues, not proof of lexical/focus interpretation.
- pause_insert: insert exactly pause_ms*24 zero samples at the resolved internal boundary on the24kHz clock. Render one whole source word for an internal-word target, then cut it at the actual aligned boundary; never create two unrelated lexical tokens. Offset all later intervals by the inserted length. A4000ms silence is96000samples, independent of provider timing. Preserve all original word/phoneme bytes outside the declared splice.
- vot_edit: render the reference stressed initial /p/ word. Detect release and onset of periodic voicing through registered alignment and pulse/F0 evidence; retain those measured boundaries. Remove the release-to-voicing interval for the default0ms requested VOT, keeping the burst and following vowel. A nonzero target repeats/crops the acquired unvoiced aspiration interval to exactly24*vot_ms samples using5ms equal-power overlap-add. If no aspiration interval is acquired, fail that requested transform with its reason; never substitute /b/ and claim measured aspiration. This manipulates the generated contrast; no universal VOT boundary or guaranteed perception is asserted.

Process nonoverlapping intervals in descending source-sample order. Multiple same-scope transforms apply VOT/phone replacement first, then pitch/duration, then explicit pause, then gain; store each step's source and result asset. Incompatible overlaps return CONSTRAINT_CONFLICT before dispatch and retain the preparation. For an ordinary splice use at most min(120samples,half each adjacent nonempty interval) equal-power crossfade; insert silence after fades. Preserve unaffected samples, save the exact splice accounting, and recompute the final sample map from output lengths. If a fade would erase a target release, use no fade at that boundary and retain a QC warning. The intentionally changed waveform must not be silently repaired by loudness processing. Final format/resampling and malformed-byte/QC rules still follow audio-methods.md; quality warnings remain warnings.

Resolve parameters once per saved preparation. Defaults instantiate the original illustrations; the LLM chooses novel valid lexical/contextual instances and specific parameters from the same typed contracts. Accepted_reference is expressed in audible dialogue whenever required to judge the target. A hidden waveform reference never makes an otherwise unannounced arbitrary speed/duration norm scorable. Listener-relevant context must survive mutation; do not generate a text relying on private norms or external facts.

Known realization failure cannot remain a confirmed scorable acoustic error. Existing component-scoped key repair/uncertainty handles affected units without changing supported textual scores. Intent-only results retain their candidate warning and unknown acoustic observation. Diagnostics are optional for ordinary publication; no repeated acoustic certification gate is added. Full development acceptance nevertheless must execute the affected acoustic feature cases against actual generated recordings, distinct from routine use.

## Control compilation rules

For every acoustic_edit, resolve unit_id and utterance_id against the same saved candidate/manifest and verify its scope is inside the planned unit's surface span. phone_pair requires both nonempty reference_ipa and mutated_ipa; the selected codepoint scope is the complete target word/phrase. vowel_duration requires positive duration_ratio and nonnull phone_start/phone_end selecting the vowel tokens in that rendered scope. pitch_duration requires at least one actual pitch/duration/gain change; word/phrase scope uses decoder word times, while syllable-specific stress/rhythm requires phone_start/phone_end. pause_insert requires pause_ms and inserts at the start boundary of scope, or at the exact decoder token boundary selected by phone_start for an internal-word pause; phone_end is unused in the latter case. vot_edit requires vot_ms and a scope whose initial selected stop/vowel can supply the actual landmarks. Nonapplicable parameters are null/empty. Internal codepoint scopes must correspond to actual G2P/grapheme associations; unresolvable scope stays an explicit failed render step. Do not interpret a prose target_label as code or generate arbitrary interval fractions. These are native semantic validations of meaningful operations, not LLM-format rejection rules or peer review.

Identity/control_variant rows preserve the generated permitted wording/realization and mark the existing control key, with no acoustic edit required unless a separate deliberate actual control realization is requested. A broad-category selection still has the same exact target/control-count semantics; native code cannot replace a requested error with a control to make rendering easier. Same-scope incompatible edits are returned as a constraint conflict before transforms, while compatible edits retain their declared order and separate repair obligations.

## Existing transport readback projection

Python /internal/v1/render retains its existing endpoint. New requests carry render_scope: full_plan with null piece/progress for legacy whole-plan calls; piece with exact existing piece_id and render_progress_asset_id for Go-controlled piece continuation; assemble with null piece_id and the all-complete progress asset. Omitted scope means the historic full_plan mode. The request retains the full frozen core plan and its digest; a piece scope selects the exact saved turn/operation indexes rather than pretending the subset is the whole plan. Python resolves the private progress/child plan and refuses a mismatching selected piece/request binding. Piece execution returns a complete piece WAV, delivery_scope=piece, its piece/progress/sample-map references, actual turns and actual receipts. Assembly returns delivery_scope=full_plan and the actual whole WAV. Streaming partial bytes cannot populate either success. Failed/interrupted work uses existing operation/error receipts and a read-back progress summary, never a success-shaped incomplete WAV. Go owns preparation-head CAS and links Python's complete scoped assets/receipt before continuing; Python does not claim a new Go head revision.

New speech results retain turns[].receipt_ids for every actual contributing call; singular receipt_id is the first real provider/model receipt for backward compatibility, null when the operation only assembles or imports native bytes. Native assembly has its own operation result/transformation asset with zero model dispatches. No synthetic provider call or merged provider-success claim is created. The final key's unit clocks use sample_map_asset_id and assembly records; the original native/source clock is retained separately.

preparation-state.render_progress_summary is a safe derived projection included on new preparation read/list responses: complete_pieces,total_pieces,first_unfinished_piece_id,ready_to_assemble. Derive it from the linked immutable progress and actual read-back assets on each head update/read; never trust client counts. Historic no-progress heads show0/0,null,false. An all-complete nonempty plan may set ready_to_assemble=true; completed/total counts are not a published playable exercise until final linkage. The UI needs no generic asset-read API or private storage key to show Resume/progress. Backup stores the underlying progress and recalculates this summary after restore.

The sample-map asset validates audio-sample-map.schema.json, including actual source clock/digest, exact output clock/digest/length and explicit transform/crossfade groups. It is a canonical typed artifact, not an unindexed opaque generated JSON document. Source bindings with a program execute that program; legacy fields/record_selector remain native documentation/history and must not define a conflicting second mapping. A no-program legacy binding deterministically projects its declared native fields under the same conversion/null/span rules without fuzzy joins; any needed join/repeated projection requires a saved program.

The auditory request includes complete selected planned_units (existing typed intent/rubric projection) and acoustic_edits, not only opaque unit IDs. Go derives these from the same saved key/mutation manifest, with all acoustic observation fields null and no earlier diagnostic/evaluator output. Imported units keep their actual source provenance in existing evidence; authored controls can be empty for imports. Send the actual structured request data as labelled inert user content, the frozen auditory prompt as trusted system instruction, followed by labelled actual target/reference audio items in that order. The local adapter uses the same order in its chat template. The judge is allowed to contradict the key; intent is not evidence of hearing.

Settings persistence uses the existing put_config operation: put-config-request includes optional speech_profiles and audio_diagnostic_profile matching configuration's typed fields. New profile updates supply complete explicit selected profile records and existing private asset/credential references; ID references must resolve in that saved configuration.
