## Distinct sets and oracle sensitivity

Each set is selected by property ID and follows case ID -> graph command/owner/scenario -> case binding. The case binding owns the exact input/expected packet. A reusable fixture supplies action/oracle and a baseline; older mode-labelled rejection/evidence/component refinements may use a different case-specific packet. New SET2 bindings and named scenario fixtures match their referenced packets exactly. New edges use the existing pending acceptance command and remain blocked/not_run; the absent future acceptance source is never presented as executable code. The set index is test design metadata, not another runtime service or learner prerequisite.

Positive includes supported outcomes such as optional missing explanation or explicit continuation. Negative includes wrong learner answers, incomplete source components, stale associations and provider/storage failures, including successful handling of those failures. It does not mean every negative input needs HTTP rejection. Named arithmetic negative packets stipulate a wrong proposed result and require the independently correct exact result; that proposed value is a test-harness counterexample, never an LLM numeric score accepted by the app.

The 122 leaf sets distinguish a true mutation, its permitted clean control, a semantically described valid repair without mandatory explanation, and a missed true mistake. The eight acceptable-variant leaves instead use acceptable assertions and overcorrection cases: G=TP=0; explicit correct acceptability has DF=DA=1 and FC=0. Calling a permitted variant wrong has FP=FC=1. None becomes a positive true-error unit. Acoustic fixtures still prescribe intended reference/target behavior with actual confirmation unknown until real audio is observed.

Formula sets retain all 42 independent expected results and add changed populations/exposures, distinct elapsed time or deduplicated replay counts. Duplication of sufficient statistics/exposure preserves a ratio; generated audio and written answers cannot supply an unmeasured teacher trait. Source/component failure variants isolate missing components from missing dictionaries. Infrastructure variants isolate unavailable dependencies from migration failure; storage/retry variants preserve frozen identities.

The finite specification checker in audit/property-test-sets-20261010/check.py validates every set/edge/packet and exercises sensitivity by deleting a case, duplicating a packet, changing polarity, inserting false decoy credit and fabricating execution. These are executable checks of specification metadata only. They neither execute the application nor establish semantic/audio/provider quality. Runtime implementations must materialize exact packets into owned request/storage/context contracts and record actual output, native receipts, sample provenance and MLflow evidence where applicable.
