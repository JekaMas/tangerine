# Concrete property and case plans

`domain/verification-fixtures.v1.json` is the finite specification fixture catalogue. It binds all 390 requirements, 405 declared properties and 1,620 positive/negative case entries by their existing IDs. Its 325 reusable packets contain literal inputs, expected values/states, rejected counterexamples and independent oracle instructions. Each case selects its exact packet and named scenario; generic definition scenarios exercise the valid/invalid pair, generic rejection scenarios exercise the rejected input, and evidence scenarios assert zero actual runs remains zero. No generic fallback assigns a fixture to an unknown requirement. Twenty-two specific named scenarios additionally refine the shared packets; every case retains its actual scenario contract for comparison.

The catalogue includes the preserved independent authored illustration and clean control for every one of the 122 categories, 42 manually stated original-equation results, 22 Lab diagnostic results and all 11 original full-source component inventories. Source records/examples are labelled constructed; they are not acquired native releases, participant answers, empirical frequencies or verified acoustic recordings. Acoustic recipes specify intended transformations and relevant evidence while actual realization remains unknown until the selected audio is observed. Context-bearing ordinary generation still follows self-contained-generation.md.

A fixture is a compact test-design packet, not a claimed fully serialized application request, installed dataset or executable acceptance test. During authorized implementation, the named owner materializes its literals into that operation's actual schemas/storage/voice inputs, preserving the stated semantics and expected results. Generated IDs/timestamps are captured from actual operations and compared through the declared associations. Use deterministic constructed inputs for arithmetic/state/storage tests; semantic/provider cases also need the selected real model output and retained receipts. Expected values are fixed before running that candidate; candidate responses cannot define their own gold. Do not silently replace a fixture's required modality or reference population.

Property/case bindings all have `observation_state=not_run`. They define what must be tested. Existing implemented cases retain their original source identity, command and source hash; their earlier receipts do not prove newly designed packets. Four former account/login case receipts are explicitly preserved as historical in audit/final-spec-closure-20261009/invalidated-historical-cases.json, and their current no-login/workspace-persistence cases are blocked awaiting actual observation. Other original bounded receipts remain unchanged. This audit executes static artifact integrity and independent constructed arithmetic only.

For each later selected case, record actual action, inputs/bindings, observed response/state/artifact hashes, every independently expected field, failure and provider/audio/Lab receipts when relevant. Do not report a full generated exercise, semantic verdict, measured sound, imported corpus or restart/restore result from a static fixture check. An implementation mismatch or unclear real semantic/acoustic reference is retained explicitly; it never becomes a fabricated pass. AI-affecting development continues to use the required selected MLflow evidence route. Ordinary use requires no benchmark, human review or Lab.
