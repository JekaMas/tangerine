# Recovery and complete usability

Iteration15 connects the existing stages; no prompt, taxonomy, recipe, numeric equation, model or speech controller is replaced. The original122category/recipe identities,42formulas and11source identities remain. Earlier unaccepted iterations do not become accepted through this increment.

## Ordinary local flow

Library links to Prepare, saved audio/attempts, reports, sources, optional review, Settings and Recovery. Prepare accepts the topic, speaker count and approximate text length; CEFR, broad families and advanced blueprint/voices remain optional. POST blueprints admits the new request once. The private Generate action calls the existing canonical-text, mutation and render owners in order under the existing270s foreground request. No stage is dispatched after cancellation/deadline or prerequisite failure. Exact native failures, completed artifacts and receipts stay saved.

Generate idempotency derives stable child keys. Repeating a completed action returns its own saved result without another text/speech dispatch. Explicit Resume loads the saved preparation/settings and uses the same stage owners; completed stages are reused. Current Settings cannot replace frozen models, prompts, voices or input. A lost response is recovered by refreshing the saved preparation list; GET/readback makes no inference and never audits accepted hashes/schema. A prior active owner keeps its existing deadline/lease/CAS semantics. There is no worker, auto-resume, canary, pregenerated bank or human gate.

The browser retains form input on errors, explains failed configuration/dependency/capability/allowance actions, exposes Stop and explicit Resume, and links completed exercises to the Library. Drafts/submitted answers/results keep their existing exact-byte and immutable revision contracts. The optional Lab is not a normal-use prerequisite.

## Consistent archive and restore

`sh scripts/tangerine backup name.tar.gz` creates a private archive under data/backups using the source-built host-native helper, Docker Compose and native pg_dump/MinIO. No host Go/Python/Node is needed. It stops every currently running application writer and optional Lab, exports native database records, all actual private object bytes (including historical/unlinked retained bytes), installed model/voice cache files and optional stopped Lab SQLite/artifacts, then restarts only services previously running. Partial exports never replace a complete destination. The complete file inventory contains actual SHA-256 and byte counts calculated while writing each new archive entry. The manifest is last; no archive reread is required at creation.

Archive format2 uses database.dump, media/<actual-key>, models/<relative-path>, lab/<relative-path> and manifest.json. The manifest records format/id/time, ordered applied migration version names, exact file inventory, secrets_included=false and model/Lab presence. No audit chain, revocation epoch, release manifest, schema-source archive, duplicate canonical digest or signature is required. Backup is an explicit local maintenance operation, not an LLM request; it has signal cancellation and no arbitrary270s corpus-size cap. Provider keys, root .env/runtime.env, provider-token files and obsolete legacy authentication rows are excluded. All actual source/domain/person annotations stay private in the archive; arbitrary imported text is not rewritten as a credentials-redaction heuristic.

`sh scripts/tangerine restore <archive-path> <new-project>` creates new isolated volumes and new private internal credentials. Its source-built storage owner admits the external archive once: ordinary regular files only, relative canonical paths, no links/traversal/duplicates or credentials namespace, manifest complete, exact entry hashes/counts and ordered migration versions compatible with this source. An older supported migration prefix is accepted; startup applies missing migrations through the existing upgrade owner. A future/unknown/reordered version is incompatible. Stored migration checksums are not re-audited.

After admission, pg_restore, private MinIO and model/Lab cache copy consume the staged accepted bytes without another schema/hash qualification. Existing target resources/configuration are refused; no merge or overwrite occurs. Failure leaves the prior workspace selected and usable; failed fresh target resources remain explicitly incomplete for inspection. Restored credentials are absent: report reconnect/key requirements, but stored audio, answers and results remain readable without provider calls. Restore does not activate the target.

`sh scripts/tangerine switch <project>` is the explicit selection action. Stop the previous frontend/application, start the target with actual dependency readiness, atomically select it only after success, and retain previous volumes/configuration. A failed switch stops the failed target frontend and restarts previous running services. The launcher reads data/config/active-project unless the operator explicitly supplies COMPOSE_PROJECT_NAME. The original project marker permits switching back to a custom-named original installation. No data is deleted by switch or stop.

The logical backup/restore operation catalogue maps to this host maintenance transport: stopping/replacing the serving API is a Docker lifecycle concern, not an HTTP handler or web Docker socket. Recovery UI presents the concrete commands and service/readback links. The old Python prototype scripts remain historical compatibility inputs, not the product launcher or an additional host prerequisite.

## Explicit erasure

Cleanup previews selected IDs or old unlinked media. Preview expands frozen document versions, dependent attempts/results/diagnostics and exact private-object IDs, plus source release/import and report/experiment rows. Shared private objects remain until their last retained reference is removed. A selected referenced asset is blocked; active foreground writers and changed plans require a fresh preview. These are business deletion/ownership guards, not repeated validation of saved payloads.

Apply requires the displayed plan digest and explicit local confirmation, locks deletion against application writers, removes selected native rows transactionally and leaves identifier-only tombstones without answer/audio bodies or retained content hashes. Private media removal follows commit and is retryable/idempotent; pending cleanup is reported honestly. Old unlinked bytes become eligible after30days; no automatic cleanup runs. External backup files remain the operator's responsibility.

Copied local Lab data can outlive native deletion. Native erasure reports that disposition, rather than claiming those bodies erased. The explicit separately confirmed local Lab purge removes that installation's entire optional Lab volume and native export copies, without inference; native results for retained work remain. No immutable hash-chain or permission-epoch system prevents user deletion.
