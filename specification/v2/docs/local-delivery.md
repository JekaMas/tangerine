# GitHub source download and local use

This is the chosen product contract for GAP-054. The project is an open-source source ZIP or clone. A formal release manifest, SBOM, signed bundle, prebuilt application images, Git metadata and workflow submodules are not startup prerequisites.

The supported host prerequisite is Docker Engine 24 or later with Compose plugin v2.20 or later, or Docker Desktop providing those interfaces, on linux/amd64 or linux/arm64. macOS uses Docker Desktop. Windows uses WSL2 with a POSIX shell and Docker integration. The helper verifies capabilities (Compose config, build, health checks, volume operations) and reports unsupported versions before writing state. Host Go, Node, Python, PostgreSQL and MinIO installation is unnecessary.

The repository supplies README.md, .env.example, scripts/tangerine, deploy/local/compose.yaml, complete application source, Dockerfiles and ordinary dependency lock files. Build contexts never depend on .git, sibling repositories, downloaded workflow submodules or this audit’s tooling. Extract the complete ZIP and run `sh scripts/tangerine start`; the launcher creates .env from .env.example automatically. Open http://localhost:3000. Fill keys only for selected key-based adapters; the ChatGPT-plan route uses provider sign-in. Startup requires no provider key or model connection and performs no inference. Runtime acceptance and its actual tested architecture/bindings are recorded separately from this contract.

The helper actions are start, stop, status, logs, backup, restore and model-setup. Selecting local speech uses `sh scripts/tangerine model-setup` to download the configured model/voice assets into the persistent cache; it reports progress/failure and stores actual digests. A failed setup retains application state and permits retry. Service synthesis does not require this action. start builds application containers locally before first launch, initializes internal secrets/storage/migrations automatically and waits for real health. Repeated start preserves local volumes and secrets. stop never deletes volumes. logs redact secrets. Backup and restore follow docs/maintenance-and-limits.md, with explicit destructive-switch confirmation. There is no account bootstrap or login.

Normal startup exposes only web on 127.0.0.1:3000. The optional explicit `sh scripts/tangerine lab` action additionally exposes its local diagnostic UI on 127.0.0.1:5000; it is outside ordinary startup readiness. PostgreSQL, MinIO, Go API and Python speech remain on the private Compose network. API and speech credentials are generated with OS randomness and persisted privately on first start; generation failure aborts startup. Configuration files containing values use owner-only access and are excluded from Git/source export. No secret enters Docker build arguments, images, browser environment, prompts, logs or DTOs.

The current starter LLM is chatgpt-plan-responses-v1 through the existing eligible ChatGPT Pro account, as defined in provider-access.md and domain/provider-access.v1.json. No Platform API key is required for that route. The original deepseek-flash-low-v1 testing profile and server-side DEEPSEEK_API_KEY remain configurable; token-billed/unknown entitlement is unavailable under the current included_only policy. Selection of another explicit configured profile is supported without silent fallback. OPENAI_API_KEY is needed for selected OpenAI operations/Whisper; AZURE_SPEECH_KEY and AZURE_SPEECH_REGION are needed for selected Azure synthesis/assessment. Missing keys disable only dependent paid operations with a clear missing-key result; stored permitted audio and historical local results remain usable. Missing mandatory local infrastructure/build inputs prevent startup. No startup provider inference, corpus download, invented exercise or canary is allowed.

Missing Docker/Compose, inaccessible daemon, occupied port, malformed/unknown settings, unsupported architecture, missing build source/locks, failed build, internal-secret creation failure, incompatible migration and dependency health failure each produce a named error and nonzero exit. Failure retains existing volumes and explains the action needed. Never claim readiness solely because containers started. Updating source preserves volumes, trusts accepted migration history and applies only missing versions through the supported migration plan; a missing supported plan stops before mutation. The concrete migration plan remains FRC-011.

First use offers Library, Prepare, Review and Results. A newly created library is honestly empty. An authored exercise is usable as soon as its actual audio and generated mutation-list key are saved; a separate case review is optional. Listening answers are checked by the LLM against that list. Full taxonomy/source/benchmark reports remain features and never block startup or ordinary use. Review is an optional LLM diagnostic, with no human qualifications.

The source distribution includes the full application, lockfiles and build contexts. LICENSE and the README explicitly apply Apache-2.0 to original Tangerine software, as selected by the actual user; third-party corpora are acquired separately under their own terms, not copied into the public source ZIP. A configured eligible LLM connection enables clean-text generation, mutations and text answer checking; a DeepSeek key alone does not establish subscription-covered API use. New audio generation uses either local model assets without a speech API key, or the configured Azure service key/region; the user chooses the backend. The launcher includes the local speech dependency and a visible model-setup action with persistent cache; no model download or inference runs implicitly at startup. Missing optional ASR/assessment keys show unavailable measurements. No startup canary or paid qualification call is required.

Optional Lab/helper subcommands and persistent SQLite/artifact setup are defined in llm-lab.md. Their source build inputs are included and add no required host installation, cloud account or inference at startup.

Application delivery follows product-data-relevance.md: no academic email, vendor account/API, complete external corpus, institutional study, benchmark completion or universal vendor/voice/platform qualification. Future acceptance tests prove the implemented flow on the selected supported backend/voice/platform with actual stored audio and answer checking.

First use defaults to local Kokoro for the LLM-key-only path. Before Generate, Settings shows local/service choice. Missing local model assets show one explicit model-setup action with progress, actual hashes, failure and retry; startup itself downloads no weights. Selecting service requires its configured speech credential and skips local setup. Save the choice before preparation, with no silent backend fallback. Existing saved explicit service configuration is preserved on upgrade.

For the practical service-to-feature/account/key mapping and starter sequence, read [service setup guide](service-setup-guide.md). This guide and provider-access.md own current subscription/local defaults; retained historical API-key-only wording is not an additional setup requirement.

The implemented Prepare and Recovery pages, concrete backup/restore/switch/purge commands and copied-Lab erasure disposition are defined in [recovery runtime](recovery-and-usability-runtime.md). Ordinary source startup requires no workflow submodule or host language toolchain.
