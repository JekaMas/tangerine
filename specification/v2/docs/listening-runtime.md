# Listening and saved answers

Iteration9 implements the listening/persistence phase of the accepted generated-exercise flow. No inference, model setup, queue, human review or external corpus is needed to save an attempt. Semantic interpretation, native scoring and feedback retain their subsequent implementation owners; a saved answer is never reported as an evaluated result.

The existing render finalizer publishes a new immutable ground-truth version and its safe Library row in the same transaction as completed preparation/case linkage. The original generated key remains retained. The published version ID is the actual immutable document ID, and its case_version_id agrees with that identity. Audio/key content and the content digest stay the same; publication status is not part of the content hash. Repeated finalization reuses the existing published source-key mapping. No review/qualification step is inserted. Historic catalogue rows without a bound playable version remain visible without a listening action; actual historical accepted renders can be finalized through the explicit render continuation.

The Library's optional case_sha256 supplies the existing start request's selected-version equality precondition. It contains no transcript, target count, category or private key. A listening version is selected by POST /api/v1/attempts with case_version_id,case_sha256,requested_language and Idempotency-Key. Starting requires published availability and linked final audio, and freezes the public item, audio/content identities, task components, answer-components-v2, scoring policy2.0.0, current complete configuration, active prompt bundle and effective evaluator profiles/prompt bindings. Select an eligible configured core checking model before starting; starting itself never dispatches it. Optional mapping-audit, feedback and adjudication profiles are frozen as configured but their missing setup cannot block ordinary listening or primary checking. Their actual dispatch retains its own model/access-policy admission when explicitly selected. Later settings, prompt activation, quarantine, retirement or successor publication cannot rewrite that snapshot. A rights restriction blocks media access explicitly; ordinary retirement/quarantine do not erase existing attempt history.

GET /api/v1/attempts/{id} returns the closed attempt-view allowlist. Public context, task components, audio path and the user's own draft are visible; transcript, units, count, raw context/bindings, source/reference clips and private provider data are absent. The actual audio digest needed by playback telemetry is the X-Tangerine-Audio-SHA256 response header on start/get/answer actions; it is metadata, not key disclosure. Audio uses /api/v1/attempts/{id}/audio with the exact frozen linked asset, audio-digest ETag, valid single byte-range support and explicit dependency failures. Reads/playback never resynthesize, infer or re-audit accepted bytes.

PUT /api/v1/attempts/{id}/answer saves while started. POST /api/v1/attempts/{id}:submit commits the exact answer as saved and freezes submitted_at before any evaluator can take it. Both accept only answer_text/requested_language as authoritative content, use Idempotency-Key and quoted decimal If-Match, and return a quoted revision ETag. Original UTF-8 answer bytes (after JSON decoding), combining marks, English/Russian content, whitespace, newlines and an empty answer are preserved without normalization. The existing20,000 Unicode-codepoint limit accepts non-BMP text; transport capacity accommodates the complete valid JSON encoding. Harmless additive fields are ignored; claimed server state/identity cannot change the stored lifecycle. Every admitted request and original language is retained with its operation. Same operation/key/body/revision replays the saved outcome; changed content/target/revision under that key conflicts. Stale writes return412 and leave the original unchanged. Each successful draft increments revision and stays started; submission increments revision, records database UTC time and moves to saved. New edits/submissions cannot replace a frozen answer. No database lock spans an inference or media call.

Iteration9 returns a truthful result-envelope with status=saved, score=null, unperformed auxiliary/feedback values and the evaluate continuation. GET results before submission conflicts. This is the exact persistence handoff for iteration10's foreground evaluator, rather than a fake background evaluation or completed grade. Closing/reopening reads saved state without making a call. The later semantic/evaluation lease owners still implement evaluating/completed/evaluation_failed/review_required and result revisions.

POST /api/v1/attempts/{id}/playback accepts the existing play-event-request. The server assigns event ID and received_at, checks the attempt/audio identity and final sample bounds once, deduplicates equal page-instance/sequence reports and rejects conflicting duplicate payloads. Unique client ordinals are retained when HTTP reports arrive out of order; arrival order is not proof of action order. A new page instance can restart at sequence0. A duplicate can replay after answer revisions without changing the original event/response revision. Received wall time is authoritative; client time, play/pause/seek/ended and positions are descriptive reports and never proof of ability or actual listening. Playback failure does not block saving an answer.

GET /api/v1/attempts returns the attempt-summary list, default50/max100, in descending original creation-time/ID order. limit and cursor are forwarded by the private proxy. X-Tangerine-Next-Cursor supplies the next key; an empty header means actual completion. Draft updates cannot reorder history. No signing/authentication service or account is introduced.

Library listening links open /listen, which starts once and switches to its durable attempt URL. /listen?attempt=... reopens the same record. Explicit Save draft and Submit answer preserve text through errors, show real conflicts and permit Refresh saved state without replacing unsaved text. After submission the answer is read-only. /attempts reads and reopens saved drafts/submissions. Audio retries reload the stored media; there is no model call. Publication, attempt snapshot/heads, canonical request receipts and playback indexes use PostgreSQL's existing document/operation/CAS primitives. Only final audio uses private MinIO. New schemas/tables add no user-facing complexity or repeated consistency audit.

Concurrent submission recovery: Refresh always displays the durable submitted answer and its submitted response language in the read-only answer fields. A different unsaved local response and its language remain visible in a separate, explicitly unsubmitted recovery area for copying. Repeated Refresh cannot relabel that buffer as submitted or overwrite the saved answer. Ordinary draft conflicts still retain the editable local draft.

Ownership: attempt_configuration.go freezes already admitted configuration/bindings; attempt_storage.go owns atomic attempt revisions/operations; attempt_media.go loads frozen media subject to current source rights; attempt_http.go owns transport/status/range delivery. The listening useListening controller owns request/retry/local-draft transitions, while page.js renders those states. No additional consistency check, service, account, or model call is introduced.
