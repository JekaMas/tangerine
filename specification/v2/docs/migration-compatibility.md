# Fresh and existing workspace compatibility plan

This defines the draft engineering migration boundary; it does not execute SQL. The supported current repository input is the exact 001_foundation.sql file and checksum recorded in audit/full-release-reconciliation-20261008/repository-drift.md. Unknown or changed migration history stops before any write.

For a fresh workspace, initialize real private storage, install the exact validated v2 schema registry/DDL and append a migration receipt. No account is created. Create no cases, approvals, teacher answers or source-acquisition records. An empty bank stays empty.

For an existing foundation workspace, enter maintenance mode, stop new writes/provider calls, make and verify a complete original-format DB/media backup, and record original migration checksums and schema/table inventory. Do not edit the original applied migration. Add the v2 namespace through a new separately implemented checksummed migration. Preserve the existing accounts, sessions and exercise_catalog tables as historical storage, with no active login route or account initialization requirement. Existing session tokens confer no activity privilege and must not become person/qualification evidence. Do not copy password hashes into v2 person records or backups exposed to browser code.

The old catalog contains only id/title/published_at/source_revision/audio_sha256. Archive those exact rows with an original-schema provenance reference. They cannot populate a published v2 case, reviewed key, linked media or approval. A real full case must be rebuilt/reviewed through the normal workflow; absent audio stays absent; no human qualification is required. Original values and hashes are not replaced by defaults. No full teacher-attempt tables were supplied in this foundation, so no teacher-result migration is claimed.

Historical 1.0 and local 1.1 contract payloads, if later imported as actual data, retain their original type/version/hash and remain read-only historical records. They are not decoded as v2 by field dropping or assumed ID equivalence. Converting them requires a separately documented exact transformation and actual source/evidence correspondence. An attempt without started_at keeps elapsed-time unavailable. Old reviewer account IDs never establish actual distinct human identity. Unknown version combinations are rejected for active publication/scoring.

The current v2 contract vector binds exact schema/prompt/registry bytes for future writes. Existing cached provider outputs are reusable only under the exact frozen binding; otherwise retain as diagnostics. Results preserve original scorer/policy version, and reconsideration appends a LLM-adjudicated result. Backups use contract_vector_sha256, migration checksums and actual source metadata. An unsupported restore version remains unavailable, rather than automatically weakening schema validation.

Before switching from foundation to v2, a future migration must verify all row counts, unchanged archived data hashes, references and no-account readiness. Failed migration/validation leaves original volumes intact and no healthy v2 claim. Restore the verified old backup under its original source if rollback is needed. Exact SQL and real migration/restore checks remain future implementation evidence; no migration or restore is claimed executed.

The answer-components-v2 policy applies only to new attempts/reconsiderations explicitly selecting it. Retain old policy vectors and original metrics. New evaluator tuples include additional_assertions and component-scoped issues; historical fields are not fabricated into new truth judgments. Policy/hash differences prevent cache reuse or paired comparisons across old/new semantics.
