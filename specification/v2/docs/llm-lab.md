# LLM Lab: prompts, context, traces and quality experiments

The selected solution is self-hosted MLflow 3.17.0. Its registry and experiment UI provide the editing/comparison workspace; Tangerine owns request construction, contextual data, native grading and the original provider adapters. Iteration 3 implements and tests the local registry/context/diagnostic tooling; provider integration and model-quality experiments remain later engineering iterations. The normal generate/mutate/synthesize/listen/check/recommend flow remains unchanged.

## Local setup and ownership

`sh scripts/tangerine lab` starts the optional llm-lab Compose profile and prints http://localhost:5000. It starts one MLflow server, with SQLite at /lab/mlflow.db and proxied local artifacts at /lab/artifacts in one persistent lab volume. The future image locks mlflow==3.17.0 and its dependencies; it does not use an unpinned latest image. Normal start does not start or require this profile. The container listens on its private interface at port 5000; the only host mapping is 127.0.0.1:5000. Existing application exposure stays 127.0.0.1:3000. Internal clients use http://llm-lab:5000. MLflow uses its ordinary local server without account/auth/workspace provisioning. Set allowed hosts to localhost,127.0.0.1,llm-lab (including their configured ports); no wildcard host is needed.

The required server invocation is `mlflow server --host 0.0.0.0 --port 5000 --backend-store-uri sqlite:////lab/mlflow.db --artifacts-destination /lab/artifacts`. Set MLFLOW_DISABLE_TELEMETRY=true and DO_NOT_TRACK=true in the server and all SDK/evaluation processes. Configure no hosted tracking URI. Seed the nine built-in prompt bindings from prompts/manifest.yaml and their context policies once by content hash; repeat lab startup reuses those versions. Create the local experiment metadata without inference. Failure/occupied port affects Lab only, retains its volume and reports the failed action. No Redis, ClickHouse, separate collector, gateway, remote assistant, hosted account or recurring evaluation service is added.

Tangerine stores authoritative bundles, snapshots, provider receipts and experiment rows in its existing document/assets storage. MLflow receives editable prompt versions and diagnostic copies. Its UI is opened by a link, not embedded through an iframe or a new authentication proxy. It never owns learner scores, mutation keys or source-acquisition status.

## Edit prompts and context, then activate explicitly

Every original stage remains configurable, including both canonical_text and mutation bindings of case_generation, extraction, mapping, optional audits/review, feedback and adjudication. Registry names are `tangerine-<prompt_id>`; context policies use `tangerine-context-<prompt_id>`. MLflow context versions contain the JSON policy defined in prompt-bundle.schema.json, tagged kind=context_policy. MLflow has no presumed autonomous context-memory service: these are Tangerine policies managed through the same versioned registry. Context instructions, component order and exact selected records are visible alongside prompt text.

A registry edit creates a new numeric version. Editing does not change the running app. A prompt bundle contains all nine stage/phase bindings, prompt text, variables, numeric registry versions or builtin origin, structured context policies and exact schema hashes. Use the new prompt-bundle schema. Resolve a UI alias only during export; store its resulting numeric version, never use mutable latest/production aliases during a running request. Builtin bundles have null registry version/name and use their exact shipped content hashes. Registering/exporting a draft can occur without a provider call or mandatory test score.

The helper contract is:

| Action | Exact input and result |
|---|---|
| `lab` | Start/open the optional local UI; no paid call. |
| `lab stop` | Stop Lab, retain its volume and active Tangerine bundles. |
| `lab export --selection <file> --out <file>` | Read a JSON selection `{bindings:[{stage,phase,prompt_name,prompt_version,context_name,context_version}]}` under prompt-bundle.schema.json#/$defs/selection with positive numeric versions, or `--builtins` instead of --selection. Resolve each stage/phase, fetch exact text/policy, and write a complete prompt-bundle JSON with its actual JCS hash. No secret or provider call. Names/stages use the manifest; phase is canonical_text/mutation for generation, null otherwise. |
| `lab activate <bundle-file>` | Import the complete bundle, preserve its actual content hash, and set active_prompt_bundle_id through the existing configuration owner. Atomic activation leaves the previous bundle active on error. |
| `lab eval <experiment-file>` | Execute the explicit llm-experiment plan serially, retain real rows/receipts and publish diagnostics to MLflow when available. Requires keys for selected calls. |
| `lab sync <experiment-id-or-operation-id>` | Explicitly export saved diagnostic rows/traces after an outage; makes no provider call. |

The main Settings view offers active bundle selection, its diff, and a link to Lab. Export uses MLflow's Python register_prompt/load_prompt APIs from the bundled Lab image; activation uses Tangerine's existing configuration/storage owner. The evaluation helper invokes a native Go entrypoint sharing the actual generation/evaluation/scoring owners, with its frozen experiment binding; the MLflow Python layer logs their outputs. It must not replace those owners with direct SDK calls or a second scoring implementation. These are local helper contracts, not new public HTTP endpoints. Existing internal operations/routes remain preserved.

At operation start, freeze the whole active bundle and effective provider parameters. Builtins remain usable if Lab is off. A requested custom bundle must already be saved locally; absence is an explicit unavailable-binding error, never silent fallback. Changing activation affects new operations only. A saved answer/key/audio/result retains its original binding. Reverting is selecting an older saved bundle, without regrading old answers. Prompt/context/schema/bundle/profile hashes all enter the existing effective-binding/input-cache identity; a changed variant cannot receive a stale cached decision.

Template variables bind named stage-input fields as data, without recursively evaluating their content. Missing referenced input is a visible preparation error; there is no secret/environment-variable template expansion. Original literal prompts have variables=[]. Context policies cannot redefine native arithmetic or bypass existing answer/key modality rules.

## Inspect the actual context and each call

llm-context-snapshot.schema.json defines the private per-attempt snapshot: stage/phase, frozen bundle and binding/input hashes, ordered component kinds, trust classification, actual asset identities/hashes, tokenizer/budget information, rendered private request reference and real provider receipt/trace/span identities. Save it with the actual call inputs; raw prompt/context bodies remain private assets. Include only request-selected source excerpts, not an entire downloaded corpus by default. Explicit version identities cover the taxonomy, recipes, saved canonical text, mutation list/key, public context, original answer, actual evidence, prior decisions and output schema as applicable.

Blind extraction has no mutation key, prior grading decisions or generated expected answer. Mapping receives the exact frozen key and submitted answer. Clean generation receives no invented mutation list; mutation receives its saved canonical text. Actual wire-role mapping follows the selected provider adapter, rather than assuming a vendor's system/developer semantics. All user answers, topic text and source content remain data; owned prompt/context policy is trusted instruction.

Show included/omitted components and their reasons, byte/token counts and exact context budget. Existing request-size rules remain: do not silently truncate the answer, key, repair alternatives, evidence or instructions. A custom policy may select optional excerpts before assembly; its selection and exclusions are saved. Too-large required context reports the component/budget conflict and retains input rather than creating an inaccurate grade. Unknown tokenizer uses the existing conservative byte bound. This does not add an empirical qualification gate.

One OpenTelemetry trace identifies a foreground operation. Child spans identify stages and individual attempts, including fallback, transport retry and semantic repair, with parent linkage and actual start/end/status. New operations get new trace IDs; link replay/dispute operations to the original without rewriting its trace. Go exports OTLP/HTTP protobuf to http://llm-lab:5000/v1/traces with x-mlflow-experiment-id supplied by saved Lab experiment setup. Python speech uses the same operation trace context. No collector or gRPC dependency is required.

Explicit span attributes are tangerine.operation_id, stage, phase, receipt_id, context_snapshot_id, bundle_sha256, binding_sha256, input_sha256, case/audio/answer hashes when present, cache_hit, attempt kind/index, requested/returned model, safe normalized error, duration_ms and reported token/cost fields. Provider headers, URLs with secrets and private answer text are not span attributes. Link the sanitized rendered messages and visible output artifacts for local inspection; hidden provider reasoning is not invented or required. Show initial reply, normalized projection, validation error and repair reply separately. Null usage/cost stays unknown.

The native receipt remains saved even if trace export fails. Export is best effort, at most 1000 ms total within the existing operation reserve, with no automatic retries, persistent queue or extended 270-second deadline. Mark exported/unexported/disabled in a diagnostic record; ordinary results do not fail because Lab is down. `lab sync` retries only export. Cache hits point to the original actual receipt and are marked cache_hit, not recorded as new inference or zero-cost benchmark observations. The Lab trace view supports filtering by stage/phase/bundle/model/case/failure and shows component inputs and normalized outputs linked to the row.

## Run reproducible quality experiments

An experiment freezes the dataset manifest/hash, each case's input/expectation assets, group/split, every variant's complete bundle/profile/configuration, selected stages, scorer definitions/version and repetitions. Use llm-quality-case and llm-experiment schemas. Expectation assets obey llm-quality-case.schema.json#/$defs/expectations; actual stage input assets obey the current selected stage input schema. Dataset rows can be explicitly constructed positive/negative examples, permitted source-derived cases, or saved actual runs with their actual origin. Constructed rows are not corpus acquisitions or independent human gold.

The starter specification covers each of the 122 leaves with positive/negative semantic scenarios and includes paraphrases, alternative repairs, duplicates, retractions, acceptable controls, false assertions, ambiguity, key defects, feedback advice and provider-failure cases. Actual starter records remain future authored fixtures, not claimed as already executed. Small selected datasets are usable immediately; report selected/observed/missing leaves and seven error-family/eight-control coverage, without requiring the complete collection to start an experiment. Acoustic metrics use actual rendered observations or remain unavailable; no native reference-audio corpus is required for ordinary text tests.

Compare at least two selected variants on the same frozen cases, grouping identity and selected reference/expectation version. Default repetitions=1; an explicit larger value measures variance. Cases and variants run serially under the existing shared one-paid-operation guard. Each existing generation/render/evaluation operation keeps its 270s deadline; a batch can contain many such operations and has visible progress/cancellation, without background scheduling. On cancellation, preserve completed rows and mark remaining rows not_run. Cost caps use existing optional accounting, not a new approval ceremony.

Scopes are stage (saved upstream input), answer_pipeline (fixed audio/key/answer), generation_pipeline (fixed request; variant-specific canonical/mutation outputs), and full_flow (also synthesize with its recorded backend). Stage comparisons of mutation reuse the same canonical input; answer comparisons reuse the same saved exercise/key/audio. Generation/full-flow outcomes are not falsely presented as comparisons on identical generated content. Replay permits a new explicit provider call with frozen inputs; it does not promise identical model output. Record cached-result inspection separately. Live repetitions bypass semantic-result cache, without disabling idempotency/retry protection.

Deterministic scorers use expected typed mappings, event correspondence, accepted taxonomy alternatives and the existing native credit propositions/formulas. Semantic quality judges use a configurable real profile supporting linguistic_audit, defaulting to the existing DeepSeek fast binding; there is no automatic OpenAI judge, second secret requirement or hidden fallback. Judge prompt/profile/receipt and ordinal decisions remain saved. A grader can assess semantic generation/feedback quality, but self-consistency against a generator's own mutation list is labelled self_consistency; it does not establish independent accuracy. Never grade candidate output against labels generated by that same candidate and call it a benchmark. Native annotations, authored assertions and independent LLM assessments retain their distinct expectation_basis.

The metric registry domain/llm-quality-metrics.v1.json owns exact diagnostic arithmetic. Per row and aggregate retain numerator/denominator or sample list, applicability, missing reason and origin. Compare paired variant deltas only on common applicable completed rows, reporting excluded/error counts; also show each variant's full completion/failure denominator. Failed rows do not disappear behind an improved average. Changes to dataset, reference, scorer or scope require a new comparison grouping. No silent scalar blending of unrelated quality/cost dimensions is introduced. No diagnostic replaces any of the original 42 learner/benchmark equations.

MLflow logs variant parameters, scalar summaries and the complete per-case JSON/table artifact. Applicable original metric values remain exact in native records; MLflow floats are display copies. Provide baseline/candidate differences, errors, coverage and trace links, including failed/cancelled/not-run rows. The operator can edit, rerun and manually activate a preferred bundle. No auto-promotion, human review, pass threshold or release gate is required. Optional user thresholds flag regressions in reports only.

## Privacy, backup and failure behavior

Full context debug copies are opt-in through llm_lab_capture_content (defaultfalse); metadata/hash/receipt links remain available. When enabled, copy only selected exercise/answer text and sanitized prompt/visible response bodies to the local Lab volume. Always strip authorization/cookies/API keys, secret-valued endpoint parameters and source personal/consent/vendor-private metadata before exporting; credentials remain separate from wire/body assets. Credential headers/environment values never become trace fields. Redacted exports have their own byte hashes and references to the private originals, not falsely identical hashes. Normalization redacts only identified secret/private fields and never silently rewrites the answer used for grading.

The existing backup includes active/saved bundles, snapshots, experiment records and referenced assets, plus the optional stopped/snapshotted Lab SQLite/artifact volume. Default backup/export omits secrets. Quiesce Lab or use SQLite's consistent backup mechanism; do not copy a live database alone and call it consistent. Restore keeps the previous workspace and reports optional Lab unavailable without provider calls. Deleting an answer/case or explicit Lab history removes corresponding copied trace/body/evaluation artifacts as well as native records; failed Lab cleanup is shown as pending and is retried explicitly, without claiming deletion completed. No automatic retention/queue is added.

[Server configuration](https://mlflow.org/docs/latest/self-hosting/architecture/tracking-server/) supports SQLite and local proxied artifacts; [usage tracking](https://mlflow.org/docs/latest/community/usage-tracking/) documents disabling telemetry. The researched release is [3.17.0](https://github.com/mlflow/mlflow/releases/tag/v3.17.0); native runtime/build observations are recorded in audit/iteration-3-llm-lab-20261010/REPORT.md; provider quality remains a future observation. Context packaging, native adapter reuse, nonblocking export and Tangerine diagnostic formulas are this project's specified integration choices, not advertised MLflow features.

Exact dataset/configuration/judge contracts, complete context and aggregation are defined in llm-lab-contract-details.md.

Mandatory AI development evidence, all inference surfaces and the selected-property completeness check are defined in ai-development.md. Ordinary runtime settings remain optional; development completion needs actual synchronized evidence.

## Iteration 3 engineering delivery

The default Lab URL remains http://localhost:5000. `sh scripts/tangerine lab --port 5001` explicitly selects and remembers another loopback port when a native service such as macOS AirPlay owns5000. Only the host port changes; internal clients always use llm-lab:5000. The helper validates the configured port, checks host availability and reads the actual published MLflow version. It never silently selects a port or changes AirPlay/system settings. Ordinary startup remains independent. Host publication uses the existing egress network alongside the private network; it does not configure hosted tracking or enable telemetry.

The exact3.17.0 multiarchitecture image is locked to ghcr.io/mlflow/mlflow:v3.17.0@sha256:78803b7afd156eced665b023554bc199a4723d4466e7cba3732f7284f3cddd11. SDK dependencies come from that immutable image. The optional TANGERINE_LAB_IMAGE execution override is for a content-verified locally loaded copy of that same image, never an unqualified alternate release. No host Python/Go/Node dependency is added to normal use.

Iteration3 supplies deterministic context/bundle construction, frozen datasets/planned tuples, native private retention, registry export/activation, OTLP diagnostic export and finite evidence verification. Actual native provider adapters arrive in iteration4 and pipeline experiment execution/22diagnostic arithmetic in iteration14 of the agreed sequence; no substitute grader is implemented in the Lab SDK. The original full evaluation contracts remain required.

`lab sync` accepts a saved diagnostic packet file or its retained asset/original operation UUID. Native storage saves the original packet before export; repeated sync resolves the same local run and refuses to overwrite differing diagnostic bytes. Content capture is explicitly selected, false by default. Original and sanitized hashes/redaction reasons remain separate. CLI protocol stdout contains only JSON; SDK display logs go to stderr. All SDK calls disable telemetry and automatic HTTP retries.

`lab verify <development-run-file>` accepts the published ai-development-run schema, reads linked native inventory/case/observer/snapshot/receipt assets and verifies actual MLflow bytes before evaluating the independent join. MLflow locators use runs:/<run-id>/native/<filename>. Required native filenames are inventory.json, cases.json, dispatches.json when observed, comparison.json when applicable, and snapshot-<observation-id>.json/receipt-<observation-id>.json per actual observation. Sanitized snapshot references resolve to saved redaction assets. Missing, duplicate, mismatched or limited evidence returns nonzero with discrepancies; zero populations remain N/A and require actual deterministic artifacts/reasons. Verification and sync dispatch no inference.

### Exact native verification inputs

The retained case-result artifact contains `cases` rows with `case_id`, `property_id` and `status`. Rows retain their actual command/results and origin. Verification resolves every selected case and property against these independently retained rows; a missing, duplicate, skipped or unperformed row cannot supply observed coverage. Executed failed diagnostics remain visible and do not become passed results or quality improvement claims. Constructed native command fixtures are labelled and are separate from workflow test receipts and real model observations.

Development verification compares the run revision/dependency snapshot with the private inventory, then reads the corresponding mounted source bytes independently. Every original declared inference surface retains its stage/phase/kind; unimplemented surfaces remain planned. Missing or changed source bytes produce incomplete evidence. LLM/judge snapshots require their saved context link; surface, effective binding and context generation phase must agree. Non-LLM inputs retain their typed execution snapshots.

Explicit diagnostic run selection must resolve to that same operation's development experiment run. Operation UUID tags use canonical spelling, so repeated sync reuses the run even when the input UUID uses uppercase. Sanitization strips identified secret field names and uses safe categorical redaction reasons; it never echoes secret-bearing field names into metadata. Native originals remain unchanged.
