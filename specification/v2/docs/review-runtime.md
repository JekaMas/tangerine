# Optional review and dispute runtime

The Library links to optional case review. Results link to reconsideration, disputes and immutable result history. No review is required to generate, publish, listen or score. Existing Settings select the configurable case_review and adjudication profiles; answers use their frozen adjudication binding, and a case-only action freezes current settings at creation. Source-imported native annotations remain source data. New machine records have null person IDs and empty human qualifications.

The internal localhost routes are POST /api/v1/reviews, GET /api/v1/reviews?case_version_id=... or ?attempt_id=..., GET /api/v1/reviews/{id}, POST /api/v1/reviews/{id}:run and POST /api/v1/reviews/{id}:reconsider. List responses use the existing cursor header and return up to50rows. `review-request` supplies purpose/case and, for an answer, exact attempt/result; dispute requires the exact nonempty statement. The server derives audio identity from the immutable selected case; an optional supplied audio hash must match. Creation dispatches nothing. Explicit Run/Resume supplies Idempotency-Key and If-Match revision. Equal requests return their saved association; conflicting reuse or stale ownership cannot dispatch/publish another result. GET never invokes a provider.

`reconsider-request` identifies a completed key-defect review, its actual unit correspondence and explicitly selected saved attempts. Each child freezes that answer's own original configuration/bundle/bindings and selected result, plus the accepted same-audio successor. Conditional mapping uses the existing mapper, not a new extraction or review stage. Completed children replay without inference. A failed/deadline child and earlier completed children remain stored; an explicit repeated selection continues unfinished work. No unselected attempt is touched and no background work is scheduled.

Review input contains complete canonical/surface ground truth, selected candidate for case review, original authored mutation manifest when one exists, all actual selected evidence, complete relevant registered taxonomy definitions/rules and the full category catalogue and actual modality. An answer action additionally supplies the exact saved answer, extraction and prior decisions. The prior_decisions context also projects actual listener proposals next to consolidated saved component statuses, without changing those judgments. A case-only dispute supplies explicit absence markers in those context components while the typed answer/extraction/prior fields remain null. Text-only models are never labelled as having heard the recording. Missing acoustic observations remain inferred/unknown. Optional blind records remain genuinely absent when no blind diagnostic was performed.

The review controller uses only Server.InvokeLLM for case_review/adjudication and conditional claim_mapping. Native bindings, prompts, schema projections, inputs, output/repair attempts, usage/context and diagnostic receipts retain the existing Lab route. Normalization wraps harmless bare/list decision containers and missing envelope metadata before the one admission. Missing substantive units, correspondence, actual references or supported component judgments remain defects. No numerical grade is accepted from an LLM.

Foreground checkpoints retain frozen resources, actual stages/failures, admitted output, stable key-ID projection and conditional mapping. Retry reads accepted values without repeating schema/hash checks or completed calls. A270-second foreground owner is required for publication; a newer epoch/base result/key successor makes an obsolete proposal diagnostic rather than authoritative. Model/storage failure preserves the original result and all accepted checkpoints for explicit continuation.

A supported outcome retains the original selection. A complete mapping defect appends native exact scores, independently optional explanation assessment and result provenance. A complete key defect appends the unchanged audio/text metadata with explicit proposed units, English rationale records and total old/new correspondence; missing decisions invoke the existing mapper once over the same saved extraction. New key/rationale/correspondence/result/review records and current pointers commit together. A generated case head and Library selection advance to the successor; old recordings/attempts/history remain accessible. Insufficient evidence never becomes an authoritative changed grade. Feedback remains independently retryable using the selected revised semantic checkpoint, with no new adjudication or numeric regrade on a feedback-only retry.

GET /api/v1/attempts/{id}/results returns the selected immutable result. Its optional result_id query selects only an actual retained revision for that attempt; unrelated document IDs are refused. The review page shows original/current versions explicitly. Neither private provider/context assets nor frozen configuration/secrets are part of learner projections.

## Logical operation mapping

The normative five runtime operations are in domain/review-runtime-operations.yaml and contracts/review-runtime.openapi.yaml. They replace duplicate orchestration implied by the original logical operation list for this feature; all native record schemas and source/import data remain retained. `start_review` maps to create purpose=case_review, then explicit :run; `get_review` maps to saved review-view. `create_dispute` maps to create purpose=dispute; `get_dispute` reads the same saved statement/status; `resolve_dispute` and `adjudicate` map to :run with the saved exact purpose/answer. `get_adjudication` reads findings from the completed saved review. `unit_map` is the complete correspondence stored by accepted key repair; `reconsider` maps to :reconsider with the original typed reconsider-request. Original blind_submit/review_disclose/review_decide represent optional imported or genuinely independent diagnostic records; ordinary review does not fabricate or require them. No duplicated peer-review pipeline is introduced. Runtime ready/failed maps to an open dispute, running to under_review and complete to resolved; imported dismissed/withdrawn states remain source history.

Relevant taxonomy definitions and rules are complete in the typed stage input, while the taxonomy context part retains the full registered category catalogue for new findings. The complete frozen registry remains saved for admission. The mutation_key context part points to the same complete stage input rather than repeating it. Prior decisions include the actual listener proposal beside saved component statuses. Historical reconsideration additionally retains the original key and the exact same-audio correspondence, so unchanged source facts remain available.

Selected-answer selection uses GET /api/v1/attempts?case_version_id=<predecessor> with its existing pagination. This optional filter follows the selected result’s actual key when a result exists, and otherwise the attempt’s original key. Returned summaries preserve the immutable heard case. The UI uses the server-filtered page, so answers already reconsidered under an earlier key remain selectable for a later same-audio repair.

Added machine findings retain the actual same-utterance source metadata and native terms; if no earlier unit covers that utterance, the recording’s actual source profile remains the media source. The appended review/receipts identify the new machine annotation separately. No key repair converts native source bytes into independently authored generated media or fabricates an original rights agreement.

New-key admission uses the same registered primary scoring domain, registered accepted/secondary IDs and fixed severity weights (minor1/moderate2/major3/communication_breakdown4). These are checks on the newly returned proposal within its single admission, not stored-data qualification. When a model explicitly rejects a component with a source-quoted unsupported assertion, a known unmet required proposition mistakenly placed in violated_proposition_ids is omitted from that forbidden-ID list. Its rejection and source assertion remain unchanged. Unknown IDs, other-option references, actual forbidden assertions and missing source rejection are preserved for normal admission/error handling; the adapter invents no semantic decision. Native conditional-mapper success and failure/resume packets are exported separately from actual local review/adjudication inference, with independent receiver counts.


The single new-output projection ignores copied server-owned unit metadata (`audio_intervals`, `context_evidence`, `source`, `verification`, `evidence_ids`, `difficulty_evidence_ref`) in proposed units: native projection retains the actual saved key/media values. Unknown substantive fields remain present for normal admission. An absent key-repair reason reuses the supplied root resolution reason. This does not invent a semantic judgment; the complete raw reply remains diagnostic. Textual unit judgments may cite that unit's actual embedded context-evidence hash as well as registered evidence IDs. Such a text reference is never an acoustic observation; unknown hashes and unsupported sound confirmation remain unavailable. The authoritative key fields are ground_truth.units, distinct from quoted listener statements and prior assessments. Actual-model fixtures inspect replacement rationale propositions and source-quoted unsupported explanation assertions in addition to numeric grades.


A textual case review assesses the linguistic key from canonical/surface text and context. Native taxonomy requirements about an audible target govern confirmation of the recording; they do not create a recording prerequisite for that textual judgment. Unobserved realization stays inferred/unknown and cannot become measured sound evidence. Case-only review has no answer mapping or answer decisions. Original answer/extraction, a later dispute, and previous assessor notes have distinct source roles: grader/key prose cannot create an omitted listener explanation. Prior statuses are the factual record of the earlier grade, while their linguistic reasoning remains reviewable. The context retains the complete prior decision once in the typed input and labels its separate source-span view explicitly.

Lossless evaluator aliases satisfied_propositions/violated_propositions become the canonical *_proposition_ids only when those canonical fields are absent. Existing canonical values are never overwritten; other unknown content remains for normal admission. An omitted unresolved_reason becomes null only for a non-unresolved component, never a fabricated reason for an uncertain one. This removes format friction without manufacturing an atomic semantic judgment or numerical credit.
