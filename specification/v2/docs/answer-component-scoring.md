# Independent correction and optional explanation assessment

This is the current user-approved answer policy, `answer-components-v2`. It supersedes inherited instructions that make explanation mandatory, mix a rationale defect into correction credit or null the primary grade for an optional explanation issue. All 27 core and 15 auxiliary formula definitions remain unchanged. Existing results retain their original policy and populations; no automatic regrading occurs.

## What is assessed

The answer can contain detection, a category, a proposed correction and an explanation. The configured mapper assesses them independently in its existing call. Explanation is always optional. Assess every supplied explanation, even when task_components.explanation=false. That legacy flag means the UI may invite an explanation; it cannot require one, skip a supplied one or add explanation to the primary composite for a new attempt.

Extract correction wording and explanation wording into separate actual source spans. For “Use works, because she takes third-person agreement, and every English verb always ends in s”, the correction is “Use works”; the two rule assertions belong to explanation. A false rationale does not invalidate a linguistically valid correction. A correction that actually changes the wrong tense, meaning or required form remains wrong. Do not choose a favorable correction from two incompatible endorsed correction alternatives.

Every additional substantive assertion within a component is represented in that component's additional_assertions: exact original codepoint span/text, supported/unsupported/unknown judgment, and the LLM's contextual reason. Assertions already represented by the existing required/forbidden propositions need not be duplicated. Combined proposition references and additional_assertions cover all substantive component assertions. A separate new error assertion remains its own detection claim; attaching it to a reason does not hide it. Quotes, examples, questions and explicitly retracted assertions are interpreted in context, not automatically endorsed assertions.

## Semantic assessment to exact credit

Use the existing eligible-unit required/forbidden proposition rubric and permit valid equivalent wording. The LLM supplies semantic judgments, never a numeric grade. For each component independently, an existing violated forbidden proposition or a verified unsupported additional assertion activates the fixed false-assertion condition and gives that component credit0/1. A definite LLM rejection of an actual supplied repair can also retain option_id=null when no valid repair option matches; that resolved rejected finding gives native credit0/1, rather than creating an artificial novel-alternative dispute. A missing option alone never grants credit or rejects genuine uncertainty. Otherwise its credit is satisfied-required/all-required for the selected nonempty rubric. A correct clause in a mixed explanation remains visible as supported, while an additional false rule makes that explanation incorrect under the retained forbidden-condition policy. This does not change detection, category or correction credit.

When no already supported forbidden condition determines zero, an unknown additional assertion or genuinely unresolved proposition makes only its dependent component credit unavailable, not zero. A verified forbidden condition already fixes credit0 even if another assertion remains unknown; retain that uncertainty in feedback without withholding the determined score. No content means supplied=false, internal credit0/1, no fabricated assertion. Explanation omission displays “not provided”, optional score N/A and no penalty. A zero-required rubric or correct alternative outside every applicable option is a rubric issue, not automatic perfection or automatic rejection.

For a true-error TP with an eligible explanation, calculate the original explanation metrics even when the legacy explanation flag is false. The standalone optional explanation score is 100*explanation.graded_accuracy (EQ/EA) over supplied eligible explanations, with exact rational transport. If EA=0 it is N/A, not zero. Preserve explanation.coverage and graded_recall as separately labelled descriptive population metrics; absence in those populations never penalizes the primary grade. For a control, FP, or unit without an eligible explanation rubric, still assess supplied assertions and give feedback; formal rubric credit is N/A with its actual reason. Do not fabricate a new rubric or infer a numeric grade from the model's prose.

If any supplied eligible explanation credit remains unknown, EK/EQ and their dependent accuracy/recall metrics are null/review_required with unresolved reason. GE/TE/EA remain actual known counts and coverage can remain available. Do not remove the unresolved explanation from EA to improve the score. scoring-input.explanation_credit is null for that component; score-result.sufficient_statistics.EK/EQ permit null. Primary counters and supported metrics remain available.

## Primary grade and result state

For new attempts, composite.enabled_components contains only selected detection/classification/correction with structural opportunities. Weights remain45/15/30 and use the original detection F1, hierarchical recall and correction graded recall. Explanation is reported separately and has no primary weight. The inherited explanation weight10 remains only in frozen historical/explicit legacy benchmark policy, never silently applied to a new ordinary attempt. The new policy ID is frozen before answering and enters result/cache/Lab comparison identity.

An issue names affected_components. The server derives blocks_final_score from unresolved primary meaning: detection/key validity or a selected classification/correction dependency. Explanation-only issues are false regardless of the old task flag. A resolved wrong assertion earns the specified zero component credit; it is not an unresolved claim. Unknown optional explanation does not change complete primary result to review_required. True uncertainty about which error was detected or which of two incompatible corrections is endorsed remains provisional under existing rules.

## Feedback, review and reconsideration

Feedback separately reports correction correctness and every supplied explanation's supported, unsupported and unknown assertions, with contextual reasons and targeted advice. No explanation means no reprimand or demand to provide one. A wrong explanation is discussed as a reason to practise the rule, not an incorrect correction when that correction is valid. Feedback failure preserves all saved scores; retrying feedback does not regrade.

The same separation applies to mapper audit, duplicate/contradiction consolidation, case review, adjudication, result revisions, diagnostics and Lab expected packets. A rationale-only dispute can revise its component assessment/feedback while retaining the already supported primary metrics and heard audio. It does not automatically declare the whole key defective. If the rationale rubric actually needs new propositions/options, a new key/rationale version is required; key-repair-projection.md defines the complete typed proposal and conditional materialization. Optional explanation reconsideration is explicit and uses existing LLM operations, with no human review or new call on ordinary reads.

Example: one true error, a correct detection/correction and the explanation “third-person agreement; every English verb ends in s”. Primary TP=1,CQ=1 and default composite=100. Explanation contains one supported and one unsupported assertion; its rubric credit=0 and feedback explains both. Without any explanation the same primary score remains100 and the optional explanation score is N/A. An unsupported correction such as “use worked” in a fixed present context receives correction credit0 independently of whether its explanation contains a correct grammatical fact.

The formula expressions in metrics.v1.yaml remain byte-preserved; its inherited global unresolved-policy header and four-component composite defaults are historical policy metadata. This document owns the current component scope/primary selection. scoring-input.scoring_policy_version is copied from attempt.scoring_policy_version; score-result and pooled cohorts retain that identity. Domain breakdowns follow the same independent optional-explanation populations and nullable EK/EQ, never substitute unknown with zero.

Persist the complete validated mapper output, including additional_assertions and both component statuses, as the existing saved stage output/asset tied to the exact extraction/answer and its receipt/cache identity. The scorer derives credits from that saved output; feedback-input.decisions receives the same evaluator-output shape. Stored feedback preserves correction/explanation item kinds from feedback-output. Result readback exposes those saved findings and exact applicable scores without another provider call; it must not drop extra assertions or reconstruct them from feedback prose.
