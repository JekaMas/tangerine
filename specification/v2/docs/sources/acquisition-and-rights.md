# Complete lossless source intake

All eleven source releases are mandatory supported full-source features. Their absence never blocks local startup or independently generated cases. Full ingestion is not a sample, an excerpt count or a derivative replacing its source. Each source remains separately visible with its expected components and actual bytes/records.

Local intake accepts an operator-supplied complete directory, archive or export. Keep original documentation/license/use agreement, release identity, every file/member, original bytes/hash, component/partition, locator and native data tree. Retain scripts and executable-looking ordinary files as inert ancillary bytes; execute none. Reject path traversal, absolute paths, links/devices, duplicate normalized paths and unsafe extraction; never execute formulas/macros/external resolution. Nested archives may be retained as inert files; expansion is a separate explicit bounded intake, with its own manifest. Configurable capacity overflow stops/reports progress without declaring a truncated release complete.

Preserve all XML elements/mixed content, XLSX sheets/cells/types/formula text/cached values/hidden sheets, JSON keys/unknown fields, M2 annotations/alternatives and TextGrid tiers/clocks. Disable XML DTD/entities/XInclude/external resolution. Unknown semantics are raw_only, not discarded. Missing source labels/learner identity remain null with source-specific reasons. Original annotations, scales, participants and consent data stay source data.

For every counting unit encountered=accepted+quarantined+rejected. Each file/member also has one disposition, including ancillary documents/code. source-format-binding lists exact source locators, target meanings, null rules and versioned conversion. The full raw inventory can complete independently of semantic normalization; report raw_complete, normalized_complete, labels_not_supplied and remaining raw_only counts separately. Do not call fully normalized a release whose required semantics are unbound.

Supported intended uses remain local_analysis, internal_training, commercial_evaluation, derivative_exercises, distribution, model_training, external_api_transfer and voice_use. Default local setup uses local_analysis/derivative_exercises; operator selects permitted uses under actual source terms. Retain source notices and any supplied agreements; no legal reviewer UI, per-transfer signed approval, grant graph or permission-epoch machinery is required. API access alone does not grant a license. User approval of specification use does not create missing third-party rights.

Before enabling optional source excerpts in LLM calls, settings explain the selected recipient/data classes and source notices. Selection is a saved local setting, not repeated peer approval. Keep personal source metadata out of ordinary prompts. Preserve actual transfer provenance and clearly report unsupported/missing operational inputs. The source pipeline never guesses a private vendor endpoint or replaces missing participant data with model-generated records.

Complete native profiles for public releases are documented separately. EFCAMDAT/private/study binding uses the lossless export protocol in private-vendors-and-study.md and efcamdat.md. Actual private columns/endpoints are supplied with the actual release; source intake and semantic conversion are separately specified. No invented native contract is advertised as acquired evidence.

raw_complete/normalized_complete/raw_only_records are exact fields in source-status/import-report. raw_only_records is a subset of accepted_records, not a fourth mutually exclusive disposition. Source-release format_profile_id/hash may be null during raw intake; normalized_complete requires the actual binding. Record-format failures retain raw bytes even when quarantined. Ancillary file dispositions count files, not additional corpus utterances/essays.

## Import completion and saved release selection

The importer assesses the selected native component/population scope once at
completion, alongside raw/normalized accounting, and persists
`import-report.full_release_missing_components`. An empty array records an
assessment with no missing components. Null/absent means unfinished or legacy
unassessed work, never a fabricated complete named release. Ordinary Sources
reads trust that stored report; they do not recount rows, reopen raw archives,
rehash stored data or introduce another approval/verification gate. Existing
legacy rows remain usable even without this extra completeness claim.

A documented count reconciliation can explain nonzero observed drift. It cannot
make an entirely absent required component present; an expected zero is valid
when the actual documented component count is zero. Keep missing/raw-only
states visible while preserving valid raw intake and unrelated exercises.

`source-status.release_import_report_ids` maps each actual release ID to its own
saved import IDs in creation order. Opening an older release selects only its
own report, rows and saved semantic binding. The legacy `import_report_ids`
projection continues to describe the latest release. If a historical response
omits the per-release projection, do not substitute another release's report.
No selected report means an unopened report, not an invented association.

Import progress also returns its saved `format_binding_id` and
`permission_grant_ids` from the frozen import. Reopening restores these exact
selectors. The release's initial permissions are only the default before an
import exists; permissions selected after registration belong to that saved
import. Clear the previous release's upload/notice selection when opening a
different saved release. Reading these stored selectors creates no new grant,
revocation check or approval step.

Standard TAR global PAX headers are container metadata, not special filesystem
entries or source records. Preserve them in the original retained archive and
continue ordinary member intake. Their presence does not authorize links,
devices or unsafe member paths. The actual OpenSLR SpeechOcean archive contains
such a standard header; complete native intake must accept it without truncation.

A successful resumed import reports current record/mapping issues. Resolved
foreground-operation failures remain in the saved issue/event history and are
not shown as records still needing attention. Actual malformed data, unknown
semantics and unresolved count mismatches retain their own visible states.
No accepted rows are revalidated or rewritten merely to refresh a status view.

## Source presentation and recovery

Sources keeps one selected release/import association, including saved binding,
permission selectors, rows and cursors. Changing source clears the previous
source’s draft metadata and conversion fields. Changing binding clears the old
import view. Superseded release/progress/row/history reads cannot replace the
current selection; a late remote export cannot attach files to another source.
This is asynchronous UI ownership, not a stored-data validation or approval gate.

Transient reads reuse the shared bounded retry owner. Known invalid input,
missing-source and conflict results use locally authored guidance. Raw backend
messages, parser diagnostics and exception payloads are never ordinary UI text.
The source HTTP owner logs the cause; API/storage retain original issue history.
Sources renders history and record warnings in place with authored explanations.
An unreadable reply still retains an available saved-import header. Unsafe writes
are not blindly repeated; the existing saved operation/import supports explicit
resume with retained progress. Failed row/history reads keep available saved
progress usable; a successful retry clears the resolved warning.

A complete converter with missing source components is incomplete, not format
unbound. Actual unconverted records retain that distinct conversion-unavailable
status. Counts and native source metadata remain available in the interface,
with readable status labels and expandable missing-component details. No
external corpus is made a prerequisite for independent exercise generation.
