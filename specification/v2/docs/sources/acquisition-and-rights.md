# Complete lossless source intake

All eleven source releases are mandatory supported full-source features. Their absence never blocks local startup or independently generated cases. Full ingestion is not a sample, an excerpt count or a derivative replacing its source. Each source remains separately visible with its expected components and actual bytes/records.

Local intake accepts an operator-supplied complete directory, archive or export. Keep original documentation/license/use agreement, release identity, every file/member, original bytes/hash, component/partition, locator and native data tree. Retain scripts and executable-looking ordinary files as inert ancillary bytes; execute none. Reject path traversal, absolute paths, links/devices, duplicate normalized paths and unsafe extraction; never execute formulas/macros/external resolution. Nested archives may be retained as inert files; expansion is a separate explicit bounded intake, with its own manifest. Configurable capacity overflow stops/reports progress without declaring a truncated release complete.

Preserve all XML elements/mixed content, XLSX sheets/cells/types/formula text/cached values/hidden sheets, JSON keys/unknown fields, M2 annotations/alternatives and TextGrid tiers/clocks. Disable XML DTD/entities/XInclude/external resolution. Unknown semantics are raw_only, not discarded. Missing source labels/learner identity remain null with source-specific reasons. Original annotations, scales, participants and consent data stay source data.

For every counting unit encountered=accepted+quarantined+rejected. Each file/member also has one disposition, including ancillary documents/code. source-format-binding lists exact source locators, target meanings, null rules and versioned conversion. The full raw inventory can complete independently of semantic normalization; report raw_complete, normalized_complete, labels_not_supplied and remaining raw_only counts separately. Do not call fully normalized a release whose required semantics are unbound.

Supported intended uses remain local_analysis, internal_training, commercial_evaluation, derivative_exercises, distribution, model_training, external_api_transfer and voice_use. Default local setup uses local_analysis/derivative_exercises; operator selects permitted uses under actual source terms. Retain source notices and any supplied agreements; no legal reviewer UI, per-transfer signed approval, grant graph or permission-epoch machinery is required. API access alone does not grant a license. User approval of specification use does not create missing third-party rights.

Before enabling optional source excerpts in LLM calls, settings explain the selected recipient/data classes and source notices. Selection is a saved local setting, not repeated peer approval. Keep personal source metadata out of ordinary prompts. Preserve actual transfer provenance and clearly report unsupported/missing operational inputs. The source pipeline never guesses a private vendor endpoint or replaces missing participant data with model-generated records.

Complete native profiles for public releases are documented separately. EFCAMDAT/private/study binding uses the lossless export protocol in private-vendors-and-study.md and efcamdat.md. Actual private columns/endpoints are supplied with the actual release; source intake and semantic conversion are separately specified. No invented native contract is advertised as acquired evidence.

raw_complete/normalized_complete/raw_only_records are exact fields in source-status/import-report. raw_only_records is a subset of accepted_records, not a fourth mutually exclusive disposition. Source-release format_profile_id/hash may be null during raw intake; normalized_complete requires the actual binding. Record-format failures retain raw bytes even when quarantined. Ancillary file dispositions count files, not additional corpus utterances/essays.
