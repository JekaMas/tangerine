# Empirical reports and quality experiment runtime

This is the implemented iteration14 adapter for llm-lab.md, llm-lab-contract-details.md, mistake-data-and-mutations.md and empirical-data-needs.md. Reports and experiments are optional local tools. The normal requested-text → mutations → audio → listener answer → LLM checking and native scoring flow has no Lab, corpus, calibration or review gate. All122leaves, original42grading formulas and11source identities remain available. No paid operation is authorized by loading or running an experiment.

## Ownership and storage

internal/empirical owns population arithmetic and difficulty. internal/experiment owns the22diagnostic equations and paired comparisons. app/empirical_reports selects accepted source records and saves immutable report/input assets. app/experiment_admit freezes new inputs once; experiment_storage owns checkpoints and foreground leases; experiment_execute composes existing provider/preparation/speech/attempt/scoring owners; experiment_scorer and experiment_judge keep independent reference calculations separate from model judgments. experiment_export creates sanitized diagnostic copies; deploy/local/lab.py alone calls the MLflow SDK, with zero model dispatches. The private Go API, maintenance command and local Next.js UI use those same owners. Migration008 adds experiment/report indexes, immutable progress history, native call links and explicit export acknowledgments. It does not change migrations001–007.

## Empirical input and populations

POST /v1/reports/empirical accepts `{title,input,attempts,source}`. title is nonempty; source is null/omitted for explicit windows. input contains population, leaves, annotated_leaf_ids, windows and decisions. Population fields are release, view, split, annotator, window, modality, taxonomy_version, crosswalk_version, label_origin, l1, cefr and task. release/view/window/label_origin must identify the selected population; nullable or unknown metadata stay unknown. One report is one selected stratum; create separate reports for different releases/views/splits/annotators/modality/crosswalk/origin. It never silently pools unrelated source representations.

Each window is `{id,fully_annotated,native_tokens,events,opportunities}`. native_tokens is an integer or null. opportunities maps a leaf to its actually annotated integer number of correct/error opportunities; absent is unknown. Each event is `{id,native_label,leaf_id,secondary_ids,control,excluded_reason}`. leaf_id may be null. An independent event keeps one stable ID even when it spans windows. Repeated identical IDs count once globally and once as presence per containing window; conflicting identities reject the new input. Secondary labels and controls never create extra primary events. Exclusion reasons, native counts, unmapped counts, annotation completeness and crosswalk completeness remain explicit. Annotated source text with an unmapped/invalid/unresolved event is not a complete project absence observation.

annotated_leaf_ids explicitly names which project leaves were inspected for absence. An omitted scope inherits explicit input.leaves, before the app expands display coverage to all122. With neither, no project absence scope is claimed. A writing source cannot create pronunciation zeros. Event share describes the actually mapped events; prevalence/opportunity/token exposure for an undeclared leaf is N/A. Unknown counts serialize as null and reasons; known zero remains `"0"`.

source selects `{import_id,member,table,annotator,leaf_by_event,annotated_leaf_ids,window_pointer}` from one accepted I13import. Native M2 uses table=sentences, exact member identity and one annotator per sentence. Omitted annotator selects the lowest integer annotator ID present per S-block, recorded as lowest_integer_per_sentence. An explicitly absent annotator supplies no annotations. Noop/invalid/UNK/Um counts are retained separately. leaf_by_event maps exact localized event IDs to actual project leaves, requires a named crosswalk_version and records operator_localized_mapping origin. Event IDs are `<import>/<member>/<row ordinal>/<edit ordinal>`. Native frequencies remain independent of project mappings.

Named imported-source adapters and readable presentation are specified in
[empirical-source-reports.md](empirical-source-reports.md). Other native/private
formats without such an adapter use the existing deterministic import program to put a Window object in source_row.projection, then select it through window_pointer (RFC6901). No second transformation language or LLM guess is added. Missing projection creates an unannotated window with empirical_window_projection_absent. Exact source release/member/partition remain attached. An unknown member is an input error. An empty selected table remains an explicitly zero observed population, not complete corpus coverage.

## Exact empirical outputs

The saved response contains id, title, source_input_asset_id, report, difficulty, origin and effectiveness_claim. GET /v1/reports/empirical lists saved IDs/titles/timestamps; GET /v1/reports/empirical/{id} returns the same saved snapshot without recalculation. report lists all122leaves, native_label_counts/native_frequencies, eligible/unmapped/excluded counts, source_annotated_windows, mapping_incomplete_windows, annotated_windows/unannotated_windows, inspected_native_tokens, sparse observed pairs and confusion rows.

Fractions retain unreduced numerator/denominator plus a reduced exact pair, or null with missing_reason. Event share is leaf eligible events / all eligible mapped events. Window prevalence is inspected windows containing the leaf / completely annotated windows. Opportunity rate is distinct annotated events / recorded applicable opportunities; absence of correct-opportunity annotations is N/A. Token density is1000×distinct annotated events / native tokens over that inspected population; missing token exposure makes it unavailable. Relationships count windows with distinct events: same-leaf pairs require at least two separate event IDs. Pair support is joint windows/N; conditional is joint/A; lift is joint×N/(A×B). Both directions are retained for different leaves. Sparse unlisted pair meaning is recorded: zero only in declared inspected scope; otherwise unavailable. decisions contains reference/predicted label strings, including explicit unknown/abstention. Confusion rows retain counts and within-reference proportions; they do not turn an unlabelled window into a negative example.

attempts contains explicit observation records `{id,participant_id,origin,case_version_id,unit_id,scoring_policy_version,first_exposure,success,followup_of,score_percent}`. success is boolean/null. Only declared genuine_teacher observations with a known participant, supported success and one first exposure per participant enter difficulty. Model/constructed rows, repeat exposures and missing outcomes stay excluded with reasons. A report cannot mix case/key/policy/unit populations. Wilson95% uses z=1.959963984540054 and the existing minimum100observations/bands; crossing bands or insufficient samples remain unrated. Paired same-participant/key/policy follow-up success change is descriptive; it is no causal recommendation-effectiveness estimate. Supplied origin is retained evidence, not independently certified human participation. Machine-generated tests never become genuine participants. Applicable full42native score results remain in fixed-answer experiment row artifacts; the22Lab diagnostics do not replace them.

## Portable frozen experiments

POST /v1/lab/experiments accepts `{experiment,assets,development,development_run_id?}`. experiment obeys llm-experiment.schema.json; assets maps portable aliases to exact JSON bodies. Already private asset/document IDs may be used instead. GET /v1/lab/defaults supplies the current complete nonsecret configuration, complete nine-binding bundle and122leaf IDs for constructing a submission. Dataset/case/expectation/judge contracts are llm-quality-dataset, llm-quality-case, llm-quality-expectations and llm-quality-judge-policy. Optional context_asset_id/context_sha256 supplies exact upstream stage context separately from the unchanged stage DTO. This is useful for saved feedback/adjudication stages.

At new-input admission, validate supplied bytes/identities and resolve aliases once. Save original submitted dataset ID/digest and the distinct resolved dataset ID/digest. Freeze complete case inputs, expectations, upstream context, model/stage configuration, nine prompt bindings, scorer quality-v1, optional judge policy and fixed-answer target/text. No subsequent row rehashes or requalifies accepted assets. Repetitions use fresh stable native child operation keys; idempotent recovery reuses completed native children. Credentials resolve through the frozen reference at dispatch and are never copied into snapshots. No mutable settings alias can replace an admitted input.

Allocate all case×variant×repetition tuples in that order, starting repetition1. Run serially through native owners: stage calls the selected stage binding; generation_pipeline creates canonical text then mutations; full_flow adds stored speech/key publication; answer_pipeline evaluates a fixed existing playable case/key/answer through native interpretation, exact scoring and feedback. A generation/full_flow request has no fabricated listener answer; its answer evaluation is a separately named fixed-answer experiment. Source-derived/native material retains its origin. Fixed-reference correspondence is required for detection/score accuracy; fresh unaligned generated events yield N/A rather than invented comparable event IDs.

Exact speaker participation, requested mutation count and requested category-family presence are measured from actual saved output. Approximate word length remains a deviation; topic/coherent level and linguistic mutation correctness use explicit propositions with their actual judge basis. Canonical preservation compares the originally accepted canonical identity with the final saved preparation identity. Native transformation admission supplies structural consistency, while linguistic success is not assumed from an admitted manifest. Acoustic requested operations, sample maps or text-only judges cannot establish audible realization. Without a relevant actual target-realization observation, audio_target_confirmation_rate is N/A; native before/after feature measurements remain linked observations, not a perceived-phone verdict.

## Execution, interruption and explicit recovery

POST /v1/lab/experiments/{id}:run runs a planned batch; :cancel records cancellation and cancels the active foreground request; :resume explicitly continues unstarted tuples with the original frozen inputs. GET /v1/lab/experiments/{id} reads progress and actual export status; the collection route lists saved batches. The long HTTP batch is synchronous, with no new batch-wide270s cap. Each native operation retains its own original270s budget and original per-stage retry deadline; no retry restarts it. Phase transitions update only foreground batch ownership. Every row retains output asset, native receipt IDs, actual trace IDs,22metric results, error and export status. States are not_run, complete, failed or cancelled; batch states are planned, running, completed, partial or cancelled. Failed/cancelled rows remain in the planned denominator and are not silently rerun on resume; a fresh experiment requests fresh trials.

Storage saves immutable progress transitions and conditional active ownership. A second foreground runner cannot finalize another owner's batch. After process interruption/expired ownership, explicit resume uses stable row/child IDs: an accepted child result is reused, a genuinely unstarted child runs, and any incomplete dispatch remains visible in native receipts. Cancelled active rows and remaining not_run rows retain separate dispositions. Diagnostic persistence after cancellation is bounded; a write failure preserves the last durable checkpoint and returns an error. No queue or automatic retry loop is introduced.

## Scorers, all22diagnostics and paired results

All22names/formulas/populations remain exactly domain/llm-quality-metrics.v1.json. Sufficient statistics, sample durations, exact rational values, known token/cost subtotals and applicability/exclusion counts are saved per row and aggregate. Failed actual call durations are included. Missing provider usage/cost is null, never free or zero by invention. Native composite reference MAE uses exact expected numerator/denominator when supplied; a nonterminating absolute error retains separate integer numerator/denominator and the actual paired-score count, never a denominator disguised as extra reference scores; the full native result remains inspectable. Repetition Jaccard forms every unordered aligned completed pair. Detection pools TP/FP/FN; macro recall pools each leaf first. Mixed self-consistency/reference observations keep the conservative self_consistency basis, never independent-gold labelling.

The diagnostic judge uses the separately frozen lab-judge-v1 policy and linguistic_audit-capable configured profile; it does not alter the original nine activation bindings. Candidate and judge never receive hidden expected labels. Exactly one supported/unsupported/unknown judgment with actual supplied-asset evidence/reason is recorded per proposition; unknown retains its missing reason and no numerical learner grade. Evidence pointers address asset contents; literal JSONPath field/index aliases and a uniquely resolved copied /body wrapper are normalized at the single admission, after resolving the actual supplied asset. Expressions, wildcards and absent targets are never evaluated or invented. Missing/ambiguous evidence is not manufactured. Correction and optional explanation judgments remain independent.

Comparison JSON retains paired/excluded tuple keys, exact baseline/candidate/delta values and reasons. Both variants use the same frozen dataset/reference/scorer/scope. Completion compares the full common planned tuple population, including failed/unstarted rows. Other metrics compare common completed applicable tuples, pooling raw populations before subtraction. Repetition pairs are formed after common-tuple selection. Full per-variant completion/error denominators remain visible. Coverage enumerates122leaves with positive/negative case counts and completed rows; no promotion threshold follows. Finite fixture/local-model results never certify all122linguistic categories.

## Local UI, helper and Lab copies

/reports provides report/experiment JSON files or editable definitions, save, explicit Run, progress Refresh, Cancel, Resume, saved lists, reload continuity and exact JSON downloads/comparisons. No login, registry or corpus is needed merely to open it. Busy/error states retain definitions and saved work. The private /v1/lab/assets/{id} route returns actual stored result/comparison JSON; it is available only through the existing local/private application boundary.

`sh scripts/tangerine lab eval experiment.json` admits/runs then explicitly attempts export. `--development development-run.json` enables tracing/sanitized body capture for the frozen run only and links its explicit development UUID. The CLI prints one experiment JSON to stdout; export/SDK diagnostics use stderr. `lab experiment-read <id>`, `lab experiment-resume <id>` and `lab experiment-sync <id>` reuse saved native state. The Go `quality` maintenance mode accepts action admit/eval/read/list/cancel/report/report-read/export/export-ack and the corresponding typed submission/report/id/resume/export_receipt fields. All use the same native owners; no helper-side model SDK exists.

MLflow sync exports immutable metadata, exact diagnostic values as display floats, selected permitted sanitized row bodies and original native diagnostic packets. Its status links go to stderr. Source/answer bodies copy only with capture enabled; known credentials/private fields are redacted. Actual copied-artifact and trace acknowledgments are saved separately, and readback marks only matching row outputs exported. The immutable pre-export diagnostic remains stable. Failed/offline Lab preserves native results and pending status; explicit sync retries copy only, reusing actual MLflow operation identity and making zero inference calls. The copied development tag links native operation runs/spans to the supplied development record. Observation verification checks independent actual dispatches against retained request/reply hashes, native contexts/bindings and actual MLflow downloads/spans. Opaque Ollama tokenizer/model-server preprocessing is an explicit inspection limit; owned wire/context completeness does not claim hidden server internals.
