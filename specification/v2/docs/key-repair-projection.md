# Persistable LLM key repair with existing inputs

The answer-checking LLM already has the necessary authored evidence: ground_truth.utterances contain clean canonical and mutated surface text; ground_truth.units contain the mistake list, repairs and explanation rubric; answer/extraction contain the listener's exact response. The saved mutation_manifest is also supplied to authored reconsideration/disputes. No external corpus, human reviewer or second mandatory review stage is required. The former gap concerned the return format and deterministic storage projection, not missing LLM knowledge.

Ordinary checking still uses extraction/mapping and existing exact arithmetic. A semantically equivalent repair satisfying an existing option is accepted immediately. A key/rubric defect can be returned by the existing adjudication role when genuine reconsideration/dispute is invoked. llm-review-output.key_repair is the complete typed key-repair-proposal. resolution=key_defect requires it; supported/mapping_defect/insufficient_evidence use null. Harmless omission of that null on a non-key-defect response can normalize to null. Missing substantive proposed units/rubric/correspondence on a key_defect follows the existing single output-repair policy; a reason string alone cannot become a revised key.

The proposal carries the exact base_case_sha256 and audio_sha256, affected_components, the complete proposed semantic unit set in the existing case-candidate planned-unit shape, all old-to-proposed correspondence relations and a contextual reason. Retained logical IDs are copied from the input. Added units/options/propositions use unique proposal-local IDs such as new:u2/new:o2/new:p2. They are semantic references, not storage UUIDs. The LLM may not mint storage envelopes, observation times, measured acoustic data, numerical grades or human approvals.

Server materialization:

1. Compare base key/audio identity with the frozen reconsidered version. Preserve the complete old result/key and original submitted answer. Unrelated active settings do not alter the selected base.
2. Save the actual proposal and receipt. Allocate new local UUIDs once for each proposal-local unit/option/proposition, retaining existing logical identities when unchanged. Store this proposal-to-local map under the operation result so idempotent replay returns the same IDs.
3. Build the full ground-truth payload from the unchanged audio, speaker/utterance/public-context/variety/provenance metadata and proposed units. Use actual saved utterance audio intervals for new text units, or actual alignment when available; never invent measured phones or precision. Existing measurements retain their original origin. Any evidence envelope needed in the new version references the same actual source bytes/observation and its old provenance, with the new explicit subject/version scope; this is not a new measurement claim. Unknown acoustic facts stay unknown.
4. Materialize each unit's complete corrections, required/forbidden rationale propositions and English rationale text. Create new rationale records from those actual fields, with server UUID/version/unit references, proposition IDs and UTF-8 text hash. No omitted key content is reconstructed from a free-form reason. Optional Russian feedback can use the existing feedback stage; no forced translation call occurs during key write.
5. Resolve the correspondence using the saved local-ID map. Every old and new unit is covered exactly once: added has empty old side, removed has empty new side, same is one-to-one, split is one-to-many and merge many-to-one. No unexplained omission or guessed many-to-many relation. Correspondence uses the unchanged heard audio. Existing corrections/rubric content not changed by the proposal is copied explicitly.
6. Apply the existing key-write ground-truth/rationale validation and hash projection. Commit new key/rationale/correspondence/review provenance and selected head in one transaction, comparing the base revision. Concurrent obsolete proposals remain diagnostic and cannot overwrite the newer selected key. This changes key content, not recorded speech or the saved mutation-history asset; an omitted unintended error is labelled as discovered key repair, not retroactively an injected mutation.

For an answer-purpose repair, map the same frozen answer to the repaired key and calculate its exact statistics. If the proposal already includes a complete decisions payload for that new unit set, remap its local references and use it. Otherwise invoke the existing mapper once with the repaired key and saved extraction; this is a conditional reconsideration branch, not another ordinary review stage. Save the new result revision and its actual processing receipts; old attempts/results remain readable and are never bulk regraded. If the key write or conditional mapping fails, preserve the old result and repair diagnostics and offer explicit continuation. Incomplete semantic evidence leaves only its actual dependent components provisional.

Explanation-only rubric changes preserve supported detection/classification/correction statistics and the heard audio. The semantic revised explanation can be remapped through the same existing role; only its optional score/findings/feedback revision changes unless actual primary evidence changed. No human review, new service or scored explanation-omission rule is introduced.

Concrete omitted-error fixture: canonical She works here. They are ready.; surface She work here. They is ready. The original key lists only work. The answer identifies work -> works and is -> are. The LLM returns both proposed units, complete repair/rationale propositions and one same plus one added correspondence. Native projection gives G=GC=TP=2,CQ=2,primary100 under answer-components-v2 on the same audio. A proposal that changes the surface wording/audio or omits the second unit/rubric does not constitute that repair. These are constructed specification expectations, not model observations.

Its hashes are clearly labelled fixture identities, not actual recordings. During projection, retained acoustic measurements and genuine difficulty population metadata come only from the existing unchanged unit/stimulus evidence; proposed unrated labels cannot manufacture or erase an observed population. A substantively changed/new unit remains unrated until actually measured under the existing difficulty policy.
