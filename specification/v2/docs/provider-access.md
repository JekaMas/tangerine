# Included-allowance setup and LLM access

The operator has ChatGPT Pro and DeepSeek access and requests subscription/limits only, without purchased usage credits or separately billed calls. `domain/provider-access.v1.json` owns the current starter defaults and billing policy. It supersedes only the historical default-selection pointers in `domain/providers.v1.yaml`, not that file's retained profiles or the earlier DeepSeek fast testing preference. Effective new configuration includes provider_access_policy. It is frozen with preparation, evaluator and Lab configuration; historical absence inherits the current policy at explicit new preparation, not retroactively in old results.

Use existing ChatGPT Pro via the official local open-source ChatGPT-plan integration and local Kokoro speech. No new LLM subscription, Platform billing account or OpenAI API key is needed for this eligible route. Eligibility remains an actual connection observation, not a promise about this account. The local app still has one workspace and no application login, roles, tenant or subscription. Provider authorization is a Settings connection, as necessary to spend an included provider allowance. The original API-key route remains configurable for other installations; included_only refuses metered/unknown routes before inference. A failed plan request never tries a Platform key or another provider.

## First use

1. Download the future GitHub source ZIP/clone and run the existing local launcher. The product remains specification-only today.
2. Settings offers Continue with ChatGPT. Authorize Tangerine in the system browser. No Codex credential file is imported, modified or copied.
3. Open [ChatGPT Usage settings](https://chatgpt.com/settings/usage), select Tangerine and disable using credits after plan limits. Record that external-setting confirmation once; no repeated approval ceremony. OAuth itself does not encode a credits-only exclusion. The 2026-10-09 live readback verified the existing Pro account and automatic reload off, but exposed no Tangerine-specific control; its registration has not yet occurred. Automatic reload off does not establish exclusion of existing purchased credits. Without confirmation the subscription connection is saved but inference is unavailable under included_only. Do not buy credits or enable automatic top-up.
4. List the account's available models. Prefer gpt-6.1-sol only if present; otherwise choose one displayed model before generation. Save the slug, catalogue snapshot and effective profile. Do not claim a fixed account allowance or availability from a sample model name.
5. Choose local Kokoro, perform its explicit model-file setup and retain the registered American/British voices. Enter topic, speakers and length. No startup inference/canary/corpus/Lab run is required.

The Pro plan is an existing entitlement verified in the signed-in account settings on 2026-10-09; app-specific plan-use eligibility remains unverified. No new purchase is requested. Limits are provider/account/model dependent. Quota exhaustion preserves the clean text, mutations, recording or answer already completed, and offers explicit retry after reset or explicit selection of another eligible local/free/included backend. Playback and saved results remain usable. Missing prices remain null, not zero. Fixed subscription price is separate from per-request cost. Included quota may be named “credits” by a vendor; only the pool bundled with a recurring plan/free tier is eligible. Purchased/top-up usage is prohibited by this policy.

## Provider connection lifecycle

`provider-connection` is safe Settings metadata. Its tokens live in a separate owner-only mounted local credential directory, outside source control, ordinary backup/export, prompts, browser storage and Lab. Persist host identity before authorization as a stable UUIDv4 urn. Keep registrations by validated subject plus issued client ID; email is only a label. A single chosen provider connection is active; adding/selecting another does not change a running frozen operation.

`provider_connection_action` takes provider-connect-request at POST `/api/v1/provider-connections:action`. Connect creates a one-use pending authorization attempt and returns provider-connect-result; select/disconnect return no authorization URL. `list_provider_connections` reads safe metadata without inference. The loopback GET `/auth/callback` accepts provider-callback-query and returns the safe connection result; Next.js displays its status and return-to-Settings action. Callback fields come from query parameters, never a GET body. Callback requests are the narrow exception to ordinary same-origin checks: exact pending state and PKCE authorize this external redirect. Callback/authorization URLs are excluded from access logs, browser telemetry and model evidence; they do not become dataset examples.

New sign-in: browser authorize endpoint `https://auth.openai.com/api/accounts/authorize`, client_id=dynamic_agent_client, agent_name_hint=Tangerine, ext_agent_host_id, response_type=code, resource=https://api.openai.com/v1, scope=`openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, random state/nonce and PKCE S256. Callback URI is `http://127.0.0.1:3000/auth/callback` for the default launcher. Use the same scheme/host/path and exact attempt URI in exchange; configured loopback port may vary. A stopped/busy callback listener does not open authorization. Retained client IDs are reused on reconnect, with no new registration identity after restart.

Validate state once; handle error before code. New success requires an issued client_id, code and matching state. Returning callback cannot replace the expected client ID. Exchange form-encoded authorization_code at `https://auth.openai.com/api/accounts/oauth/token` with issued client_id, code, code_verifier, redirect_uri and resource. Validate ID-token signature/JWKS, issuer, audience, expiry, nonce and selected returning subject through OIDC discovery. Use token-response granted scopes: missing chatgpt.tokens.use.direct gives connected_no_usage and zero inference. A denied/incomplete flow never overwrites an active registration. Pending attempts expire after ten minutes; restart clears them and requires reconnect, without losing the stable host/issued registration.

Persist returned access/refresh/ID tokens, scopes, expiry and earliest_refresh_at atomically in the protected file, with 0600/0700 Unix permissions or owner-only Windows ACL. Refresh the selected session serially with its issued client ID and latest refresh token, grant_type=refresh_token and resource; omit scope. Replace rotating credentials together. Invalid/revoked grants require reconnect; transient refresh failure retains the prior file and reports unavailable. Disconnect stops new dispatch, attempts refresh-token revocation using OIDC discovery's revocation_endpoint, clears local tokens and retains host/client metadata. Unconfirmed remote revocation is displayed honestly, with a provider Settings link. Frozen operations never swap to another registration; refreshed tokens for the same validated registration are permitted.

Connection metadata is a persistent document in the existing PostgreSQL document store; pending state/nonce/PKCE are transient server-only connection state. Secret files use the existing mounted-secret mechanism and are excluded from ordinary workspace backups. Restore preserves references and saved content but requires reconnect on a different host; it never impersonates the old host or invents new credentials. Connection scopes, selected registration ID, auth_method, billing_mode and policy identity accompany the effective binding and request lineage. Raw token/code/hint values are never hashed into content-addressed artifacts.

## Responses transport

ChatGPT-plan requests use public POST `https://api.openai.com/v1/responses`, bearer OAuth access token, store=false, stream=true, tools=[], complete array input and trusted instructions/developer messages. No explicit system input or private ChatGPT backend endpoint. Omit preview-unsupported fields, including temperature, top_p, max_output_tokens, previous_response_id, background, conversation, prompt, metadata, safety_identifier, truncation, top_logprobs, max_tool_calls, moderation, multi_agent, prompt_cache_retention and user. Nullable max_output_tokens/temperature describe omission, not a wire null. Context is sent afresh from the exact frozen local snapshot; response IDs do not create provider-side persisted history. Reasoning options are sent only when supported for the selected model; null means absent.

GET `https://api.openai.com/v1/models` with the same token reads `models`; display visibility=list entries in server order and bind their actual slug. Save actual model and catalogue receipt; no model is silently substituted after inference starts. Collect visible output events privately. Accept only response.completed as a successful stage, then apply existing tolerant semantic projection. response.failed, response.incomplete, error or interrupted stream never supplies a grade from partial text. Preserve actual status/code/body/request ID and all output received. Usage-limit/unavailable errors, including subscription_sharing_usage_limit_exceeded and subscription_sharing_usage_unavailable, stop dispatch and show Manage usage; they do not trigger automatic repair/retry paid work. Existing transient transport retry and output repair budgets otherwise remain inside the same foreground deadline. Provider token streaming is internal transport, not a new app realtime workflow or queue.

This route does not support audio input, speech synthesis, transcription or file-upload API. Ordinary free-text grading uses clean/surface text, mutation key and answer; it does not require an audio-input model. Actual disputed sound needs the existing separately supported acoustic evidence path, with unknown observations preserved. LLM Lab records the exact serialized supported request, stream terminal state, native receipts and account/model/policy references; secrets are excluded. Imported historical profiles default auth_method=api_key/billing_mode=unknown and are not silently treated as free. Local Responses runners require a declared private endpoint and actual local model digest; no cloud tag substitution.

Connection/callback/billing mismatches use the existing CONSTRAINT_CONFLICT error; missing credentials use MISSING_CREDENTIALS; transient authorization/inference failures use PROVIDER_FAILURE, incomplete output PROVIDER_INCOMPLETE, and quota failure the existing LOCAL_BUDGET_EXCEEDED envelope with actual provider code retained privately. UI presents Manage usage for the last case. No new error-code family or retry loop is needed. GET callback errors return the safe error envelope and Settings link; no response includes authorization codes/tokens.

Connection state ready means valid identity, required plan-use grant and recorded credits-after-limit exclusion. Missing the grant or that exclusion keeps the connection connected_no_usage; it can still be saved/listed. Limit/unavailable states block new dispatch and preserve selected registration identity. This does not assert a programmatically verified external billing setting.

The starter setup generates no exercise corpus in advance. Each explicit new exercise request invokes the configured LLM for clean text and then mutations before rendering audio. Stored replay and matching completed-checkpoint resume reuse only the explicitly selected exercise; they are not content-generation substitutes.

Account registration is distinct from app connection: OpenAI dynamically registers Tangerine during its own OAuth flow, not through a separate developer signup. The callback/token adapter is implemented and has native protocol/storage tests. Actual own callback attempts failed at token transport; no usable grant is claimed. No registration is attempted with a stopped callback listener or another app's credentials. ## Implementation clarification: Settings configuration readback

`configuration-view` may include the complete safe `configuration` object,
validated by `configuration.schema.json`, in addition to its existing summaries.
The object contains references and parameters, never credential values. Its
self-digest and the revision ETag bind editing/readback to the actual saved
configuration. PUT retains the existing closed request and included-only access
policy; failed validation or stale revision leaves the prior configuration intact.
The field is optional for compatibility, and Tangerine's Settings owner returns it.
Native/hosted evidence remains separately qualified as described in
`docs/development/PROVIDERS.md` and the iteration audit.

For a provider with observed schema-decoding support, the optional structured_output=true profile setting passes the complete registered output contract through text.format. Omitted/false preserves plain semantic output and the existing projector. This is an explicit per-profile capability choice; ChatGPT-plan mode does not enable unsupported formatting fields. Existing same-profile unsupported-capability fallback remains bounded by the original operation budget. The frozen effective binding includes the selected setting and actual bundled wire-schema digest. No paid fallback or extra semantic-review stage is introduced.


An optional `response_format` selection (`text`, `json_object`, `json_schema`) overrides the legacy `structured_output` boolean. Absence preserves the original behavior. `json_object` constrains JSON syntax only; the complete typed stage schema remains in context and the ordinary single new-output admission remains authoritative. Ollama Responses currently translates only `json_schema`, so its local adapter projects syntax mode as `json_schema` with the minimal `{"type":"object"}` schema. This avoids an unsupported full-contract grammar without pretending the decoder enforces semantic fields. The effective selection and actual wire are frozen/captured. Unsupported ChatGPT-plan format requests fail through the existing constraint error; no billing fallback is enabled. References: [Ollama Responses converter](https://github.com/ollama/ollama/blob/main/openai/responses.go), [structured output documentation](https://docs.ollama.com/capabilities/structured-outputs). Actual local acceptance, rather than advertised capability, qualifies this profile.


## Explicit Gemini Free text selection

The optional native `gemini_interactions` text adapter uses `https://generativelanguage.googleapis.com/v1beta/interactions`, API-key authentication through the private `GEMINI_API_KEY` environment reference, `billing_mode=free_tier`, nonstreaming foreground execution, `store=false`, `background=false` and no tools. For this operator it may be selected only with the already admitted project with billing unlinked. A configured key or profile label alone never proves a free entitlement for another installation. There is no automatic provider change after a local model fails. New selection creates new frozen preparation settings; earlier failed checkpoints retain their original model.

The exact owned system instructions remain in system_instruction; the complete existing input-message array is serialized as JSON in the native text input, preserving order, roles and verbatim data. Explicit temperature/output cap map to generation_config; unspecified reasoning is omitted. An optional structured schema maps to native response_format type=text/mime_type=application/json/schema, rather than OpenAI Responses fields. Every actual request is saved before dispatch without credential headers. Native completed model_output text is concatenated in order; incomplete output cannot become a key or score. Preserve raw response and actually returned model/interaction ID. Native total_input_tokens/total_output_tokens/total_thought_tokens/total_cached_tokens map only when reported; unknown usage/cost stays unknown. Resource-exhaustion/HTTP429 stops as LOCAL_BUDGET_EXCEEDED without another attempt or paid fallback; missing credentials dispatch zero calls. Other existing retry/repair and270-second foreground limits remain unchanged.

This adapter serves all existing text roles without changing prompts, taxonomy, formulas or native score arithmetic. Audio judging remains the independently selected speech diagnostic profile. The 2026-10-22 local incident established that the installed GPT-OSS20B can fail a general full-category mutation request despite protocol/release fixture passes; local qualification is task-specific, not a guarantee of arbitrary model quality. Current actual provider quality is recorded in audit/generation-repair-20261022/REPORT.md.

Primary wire references: [Interactions API](https://ai.google.dev/api/interactions-api), [text generation](https://ai.google.dev/gemini-api/docs/text-generation), [structured output](https://ai.google.dev/gemini-api/docs/structured-output).
