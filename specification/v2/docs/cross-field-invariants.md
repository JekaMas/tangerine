# Cross-field consistency

Identity: each case/key/audio version is immutable while referenced; a result revision names the answer, case, effective evaluator profile and arithmetic policy it used. Local request envelope fields are server assigned; supplied source IDs/times are retained as source metadata. A stale revision protects competing writes; no account/role identity is required.

Claims: every substantive extracted assertion has one retained mapping decision; attachments preserve their original spans; retraction applies only to an explicitly identified earlier assertion. Coverage is server derived from claim/attachment spans and remaining source text. Unknown category aliases may map semantically to existing taxonomy IDs or remain unknown without losing detection. Duplicates do not increment TP or FP. Contradictory endorsed assertions are retained and resolved by LLM adjudication when evidence supports a resolution.

Correction/explanation: supplied flags derive from actual frozen source spans. A missing span has no supplied content and receives no credit. Satisfied/violated proposition IDs must belong to the selected unit/option. A forbidden proposition or unsupported additional_assertion gives zero only for its actual component; when no verified forbidden condition already fixes zero, unknown semantic content gives null only for that component. Otherwise credit is the exact satisfied-required count over required count. A correct new wording can satisfy the existing rubric without a human-reviewed wording list. A genuine rubric/key defect creates a new version rather than silently changing its denominator.

Review: new origin=llm records have null person/adjudicator IDs, empty human qualifications and real provider receipt references. Existing origin=source_import records retain original native human fields. Machine review, blind annotations, rationale, correspondence and adjudication remain supported; two people, competence attestations and signatures are never prerequisite fields for a new review.

Sources: every supplied file and parsed record has a disposition; understood and raw-only records are separately counted. All scripts/docs/ancillary files remain inert inventory. accepted+quarantined+rejected equals encountered records for each declared counting unit. Missing source fields stay missing, including withheld test labels. Native scales/offsets/annotators are not guessed from project expectations.

Results: zero-population metrics are N/A; scoring errors do not become perfect grades. Feedback failure cannot change a stored score. Optional mapping audit disagreement is a diagnostic; only genuine unresolved scorable meaning may make a result provisional. Imported stale human review fields do not block an LLM workflow. Every feature/source remains available independently of full benchmark completion.

Current answer-components-v2: score correction and optional supplied explanation separately, retain actual additional_assertions per component, and derive issue blocking from affected_components. Assess all supplied reasons; absence, falsehood or uncertainty in explanation cannot erase a supported primary grade. EK/EQ may be unknown while primary sufficient statistics remain known. See answer-component-scoring.md.
