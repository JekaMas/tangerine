# Simple local product — current specification

The user's latest request selects a single-person local application that anyone can start with their provider keys. This document is a normative scope overlay. It supersedes baseline account, login, tenant, access-role, public API and production-authentication requirements. It changes product requirements only; no application code is changed in this increment.

## Install, start and configure

The supported user prerequisite is a running Docker installation on amd64 or arm64. The release supplies the pinned Compose bundle, images/build inputs, default provider profile and a launcher. The intended commands are `cp .env.example .env`, edit the provider key values, then `./tangerine start`; open `http://localhost:3000`. The launcher is a future deliverable, not an existing executable or verified startup. It handles dependency readiness, migrations and private storage automatically. Users do not choose container versions, provision databases or object storage, set up an API gateway, or create accounts. Internal database/storage secrets are generated locally once, stored outside version control with owner-only file access, reused on restart and never printed. Their exact bootstrap/rotation mechanism remains an engineering definition under GAP-054.

The supplied default LLM profile is `deepseek-v41-flash-local-test-v1` using the server environment reference `DEEPSEEK_API_KEY`, with the documented model/transport/settings in docs/llm-configuration.md. Users can select another explicitly configured, qualified LLM profile without code changes; they do not need to edit every processing-stage binding. Advanced provider configuration stays server-side. Codex configuration and credential stores are never application mounts. No key value is copied from Codex in this spec update.

Opening the app, viewing the library and playing existing approved local audio require no provider call or key. Missing LLM credentials block only LLM-dependent operations with a clear configuration message. Real synthesis, ASR and pronunciation assessment use their separately configured speech profiles and may require additional provider keys; the UI explains which operation needs which key. An LLM key alone does not authorize or replace speech synthesis. Unavailable keys/providers do not trigger a fallback. All cloud transfers retain applicable source-use permission and disclosure requirements.

## One workspace and one interface

There is exactly one installation-owned workspace, `local`. There are no accounts, passwords, login/logout screens, session cookies, role assignment, tenant selectors, invitation flows, admin console or externally supported API/SDK. The operating-system user controls the installation. All functions appear as ordinary views: Library, Prepare, Review and Results. Corpus import and provider configuration are local tools/settings in that same workspace, without an administrator role.

The normal teaching path is open a published exercise, listen to stored audio, type one free-form English or Russian answer, submit, then see the saved result or an explicit review/failure state. It requires no timeline labels, microphone, stream, queue or remote service registration. The library honestly starts empty until genuine reviewed content is available. Preparation/review tools remain accessible to the local operator but are not prerequisites for logging in or completing an already published exercise.

Author, reviewer, teacher, publisher and adjudicator denote activities and evidence responsibilities, not access-control principals. The operator records actual people and qualifications for review without creating application accounts. Two independent qualified people are still required; acoustic cases require phonetics competence; unresolved disagreement requires a third qualified adjudicator or blocks publication. Local records attest who supplied observations and retain supporting evidence. Entering names or an operator attestation does not prove external identity or independence. The complete person/qualification/conflict/annotation schemas remain GAP-010/011. LLM output cannot create a human approval.

## Disclosure and trust boundary

Teacher exercise HTML, payloads, audio metadata, errors and caches omit transcripts, keys and error counts before submission. Blind-review views withhold planned keys until the reviewer has saved their independent annotation. Extraction requests remain blind to the key. Authoring and review views intentionally expose their permitted evidence at the relevant workflow stage. The same local operator can navigate to authoring; this product provides no adversarial secrecy or security isolation between human roles. Source corpus restrictions and immutable evidence ownership still apply.

Only the web port binds to `127.0.0.1:3000`; other services remain on the internal Compose network. The supported product refuses non-loopback exposure configuration. The browser uses same-origin requests; mutations reject invalid origins/hosts, without login credentials. These checks mitigate accidental browser cross-origin access and do not authenticate a local operating-system process. Provider keys, database/storage credentials and raw identity/consent records never enter browser responses, image layers, prompts or logs.

## Internal engineering boundaries

Keep the prescribed Next.js, Go, PostgreSQL, private MinIO and Python speech services as a bundled implementation detail. This increment does not approve a storage or speech substitution. Specify only the internal operations needed by the interface, imports and recovery, with exact payloads, errors, revision/idempotency and media-range rules. GAP-001 still requires those definitions; it no longer requires a public API, bearer tokens, account endpoints, tenant namespaces, a general admin API or an SDK. Internal service credentials are not user authentication.

Attempt data uses contracts/local/attempt.schema.json version 1.1.0: remove baseline tenant_id/user_id, require workspace_id equal to local, retain all answer/hash/component/policy/state/revision/idempotency/lease fields and constraints. The baseline 1.0.0 schema remains preserved. Old data cannot silently be relabelled: future migration must explicitly identify baseline records, verify references/hashes, map retained installation data to local, preserve old identity references as historical migration evidence, and reject collisions or incompatible records. GAP-003/055 still require the exact migration/compatibility protocol. Review person IDs are evidence references, not account IDs. In recovered ground-truth and verification-report schemas, reviewer_id and review_decisions retain their structural fields but their formerly authenticated descriptions are superseded: they reference genuine local person/qualification/observation evidence, without login identity. In approval-record, owner_identity_ref points to the actual scoped user decision/source evidence; it is not an application account and cannot be supplied by a model. The local scope interpretation is versioned as local-scope-1.1.0; exact original schemas remain unchanged and their semantic guards follow this overlay.

Bound local provider work, archive decompression, request sizes and storage use. No per-user/tenant quotas, billing or multi-tenant reservation service is required. The exact resource bounds remain GAP-031/052. Stored approved audio remains playable when generation is disabled or its budget is exhausted. Backup/restore is delivered through the same launcher, with consistent database/media snapshots, hash checks and explicit incompatible-restore rejection; it is a local tool, not a backup-management service. GAP-053 retains exact backup definitions. Retention and permission revocation remain operator responsibilities under GAP-051.
