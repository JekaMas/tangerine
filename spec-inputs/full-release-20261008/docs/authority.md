# Authority and completion

This package is a standalone specification candidate. It does not modify commit `203c1f1`.
The supplied gap reports describe that commit. Its repository bytes are not available in this work environment.
The original ZIPs and reports in `inputs/` are historical evidence. They are not competing active specifications.

The owner requests a full first release, all named sources, both EFCAMDAT derivatives, and permitted private vendor access.
Those requests do not create third-party rights, real reviewer evidence, or nonexistent private APIs.
They also do not authorize new mocks or fabricated acceptance data.

Apply authority in this order:

1. Apply actual owner instructions and actual scoped approvals.
2. Apply this package's explicit local scope and its closed contracts, subject to unresolved approval records.
3. Apply the behavioral requirements under the active OpenSpec change.
4. Apply the exact metric registry for equations and `docs/math-and-judgments.md` for populations and transport.
5. Apply the source-specific profiles only to matching, rights-cleared source releases.
6. Treat implementation and historical packages as non-authoritative when they conflict with these definitions.

A contradiction between a contract and its procedure is a specification fault. Do not silently select the easier behavior.
An implementer must record the contradiction and stop the dependent action.
Unrelated work can continue. No successful placeholder can replace blocked work.

## Three separate completion states

Definition closure means that a known requirement has exact inputs, outputs, rules, failures, and an authoritative artifact.
It does not mean that an application implements the requirement.
Implementation closure needs actual code and observed tests against that code.
Release closure also needs actual source rights, acquired data, audio reviews, and frozen holdout evidence.

`definition_complete` identifies an engineering contract completed in this candidate.
`definition_ready_approval_required` identifies a complete proposed policy without the previously requested scoped owner approval.
`external_contract_missing` identifies a source format or private interface that is not available.
`integration_unverified` identifies the unavailable current repository snapshot.
No status in this package means that source assets or runtime acceptance were fabricated.

## Full release rule

A full release requires every mandatory requirement, every required corpus component, and every acceptance gate.
A running empty interface is an intermediate implementation result, not a full release.
One successful exercise does not satisfy complete taxonomy or capability coverage.
A source access error does not change a full-source requirement into a comparison-only requirement.
A summary, adapter shell, configuration field, or proposed test is not completed implementation evidence.
