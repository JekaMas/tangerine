# DEC-001: Linguistic audit contract

Status: proposed; not approved. Owner approval reference: null.

## Affected paths

domain/providers.v1.yaml; prompts/linguistic-audit.v1.txt; contracts/linguistic-audit.schema.json

## Existing dependency

See audit/open-decisions.json for the supplied finding and runtime rule. This proposal never creates an approval record or claims that the original property has been resolved.

## Proposed behavior

Use a separate audit role with a fixed input containing case ID, revision, exact canonical/surface text and declared context. Return only anchored linguistic findings or an explicit abstention. No reviewer identity, signature, phone observation, numeric score, corpus permission or publication approval may be returned.

## Exact boundaries and remaining source dependency

The proposed prompt and closed output schema are under audit/decisions/drafts. An application wire contract still requires reconciliation with the missing original case and evidence schemas. Reject unmatched spans, wrong revision, unknown category IDs and any extra fields. Provider refusal or unsupported linguistic certainty must return abstention, never a successful human audit.

## Acceptance and rejection

Positive: the exact source-bound artifact and real owner decision authorize this ID only, and the actual dependent owner conforms to the proposed contract.

Negative: missing/borrowed approval, changed artifact, unsupported evidence, provider refusal, invalid scope or expired permission leaves the affected operation blocked. Independent runtime tasks continue.

## Environment, risk and removal

Local development only until explicit broader scope. No unapproved external corpus transfer. Drafts expire when their original source contracts or proposed behavior change; re-review the changed scope. Remove/revert a draft without modifying imported sources or prior decisions. No production approval inheritance.
